**Tentative date:** 2026-08-24 · **Candidate version:** `RELEASE.2026-08-24T00-00-00Z` · **Status:** Draft

This candidate moves the `pgsty/mc` client to Go 1.27.0, aligns its shared dependency stack with the current SILO server, fixes a pre-existing panic in JSON-formatted Prometheus metrics, and makes third-party license notices deterministic and present in every release format. Command names, flags, configuration paths and formats, package naming, and the S3/admin wire protocols remain unchanged.

## Toolchain and Go Modules {#toolchain}

- The module, container build stage, Linux/macOS/Windows CI, cross-builds, tidy checks, and vulnerability analysis all use **Go 1.27.0**.
- The local build prerequisite is Go 1.27.0. The macOS build floor becomes 13.0 because Go 1.27 no longer supports macOS 12 and earlier.
- The Go-maintained module family is current: `x/net` 0.58.0, `x/sys` 0.47.0, `x/term` 0.45.0, `x/text` 0.41.0, `x/crypto` 0.55.0, `x/mod` 0.40.0, `x/sync` 0.22.0, and `x/tools` 0.49.0.
- `golangci-lint` remains outside the product module graph and is installed independently at the pinned `v2.13.1` through the Go proxy/checksum path.

## SILO Dependency Alignment {#dependency-alignment}

- `github.com/minio/pkg/v3` now resolves to the maintained [`github.com/pgsty/silo-pkg/v3` v3.11.0](https://github.com/pgsty/silo-pkg/releases/tag/v3.11.0), matching the server. Import paths remain upstream-compatible.
- The related etcd modules move together from 3.6.9 to **3.7.1**, which includes the fix for [GO-2026-6107 / CVE-2026-73500](https://pkg.go.dev/vuln/GO-2026-6107).
- `grpc-gateway` moves to 2.29.0, `zap` to 1.28.0, `go.yaml.in/yaml/v3` to 3.0.5, and the two `genproto/googleapis` modules to the 2026-05-26 revision already used by SILO.
- `go-systemd` deliberately remains selected at 22.6.0 through SILO's shared portability pin: the 22.7.0 daemon package does not compile on NetBSD, while mcli itself links only the journal package.

## JSON Metrics Panic Fixed {#metrics-fix}

`mcli --json admin prometheus metrics` previously panicked for both v2 and v3 metrics APIs:

```text
panic: Invalid name validation scheme requested: unset
```

The defect is present in the published 20260804 and 20260806 clients. `madmin-go/v3` constructed the zero value of Prometheus `TextParser`, which is invalid with `prometheus/common` 0.66 and newer. mcli now constructs the parser with `UTF8Validation`, matching the upstream madmin fix, returns normal parse errors instead of panicking, and emits metric families in deterministic name order. Plain-text metrics output is unchanged.

## Third-Party Notices and Artifacts {#notices}

- `CREDITS` is generated from the union of the runtime modules linked into all six release targets: Linux, macOS, and Windows on amd64 and arm64.
- Replaced modules are attributed to their actual source repository; modules without an archived license file and secondary `LICENSE`/`NOTICE` files are handled explicitly.
- CI regenerates and compares `CREDITS`, so dependency changes cannot silently leave it stale.
- `LICENSE`, `NOTICE`, and `CREDITS` now ship in GoReleaser archives, DEB/RPM/APK packages, development images, hotfix images, and formal multi-architecture container images.
