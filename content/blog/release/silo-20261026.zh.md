## Server：自 20261018 以来的修改 {#server-20261026}

<span id="server-20261025"></span><span id="changes"></span>

- **LDAP 与 IAM（[#250](https://github.com/pgsty/silo/pull/250)）：** 修复规范化 LDAP DN 过长导致无法登录的问题。当合法 IAM 键的单个 ASCII 路径分量超过 255 字节时，可选 IAM 记录读取将其视为“记录不存在”并继续按组策略登录；但无法读取的吊销记录与底层存储故障仍严格按 Fail-Closed 拒绝，且对象后端仍不支持直接写入超长路径记录。此外，策略重载在访问底层存储期间不再持有认证缓存锁，仅在完整加载成功后原子替换缓存并保持 IAM 写入顺序；请求取消信号会传递至 KMS 与 SSE-S3 解密路径，同时不缩短调用方的策略查询超时。
- **内置策略 Reset 与实时桶清单：** 对内置策略执行 Reset 后，首次读取即可立即恢复原生策略定义；延迟到达的 peer/etcd 通知会重新加载已提交状态，不会覆盖后续新修改。策略在用检查、删除修订号与自定义策略删除行为保持不变。Console 的 `account-info` 接口改为读取实时存储桶清单，创建或删除桶后刷新页面即可看到最新结果（对象用量统计仍由后台扫描器异步更新）。
- **多池删除保护（[#257](https://github.com/pgsty/silo/pull/257)、[#256](https://github.com/pgsty/silo/issues/256)）：** 普通删除与批量删除改为先清理非权威池中的旧副本，再删除权威池副本，从而在部分失败时保住最新权威副本；同时为新建删除标记选择可用存储池，并保护仍被其他存活副本引用的远端分层对象。
- **版本桶生命周期过期（[#253](https://github.com/pgsty/silo/pull/253)、[#252](https://github.com/pgsty/silo/issues/252)）：** 当生命周期过期规则只是追加删除标记时，完整保留上一版本的远端分层数据（包括暂停版本控制桶中的非 `null` 版本）；只有当历史版本被真正永久清除、且没有任何存活引用依赖其底层载荷时，才回收远端分层数据。
- **分片上传复制（[#255](https://github.com/pgsty/silo/pull/255)、[#254](https://github.com/pgsty/silo/issues/254)）：** 为复合 CRC 分片对象复制透传 `FULL_OBJECT` 校验和类型，避免目标站点因按分片复合模式重算校验和而返回 `BadDigest`。
- **存储 RPC 与超时语义：** 转发存储 RPC 删除选项（包括覆盖写回滚所需的旧数据目录），并保持既有的磁盘/RPC 超时、请求取消、对象锁、读仲裁与自愈策略。正式版在 [`dcc2f20ba`](https://github.com/pgsty/silo/commit/dcc2f20ba) 中撤回了 20261025 草稿里的已接纳 I/O 排空等待与逐对象变更锁方案（含 [#258](https://github.com/pgsty/silo/pull/258)），详见[多池对象一致性设计记录](/zh/blog/design/multi-pool-object-consistency/#maintenance-20261026)。
- **依赖、打包与交付：** 更新 SFTP、etcd、NATS 及云厂商 SDK 等 Go 依赖；保留 Kafka 2.1 默认协议版本、CLI 输出格式与 NetBSD 兼容版本；修复旧版 DARE v1 解封逻辑（新写入继续使用 v2）。容器镜像、校验安装脚本与 Helm 客户端任务统一内置 mcli 20261026。Windows 归档改用 ZIP 格式，静态构建 `curl` 升级至 `8.23.0` 并附带下文的证书信任配置说明；同时修复了最终刷新 SBOM 与构建溯源时的 RPM 签名校验。
- **文档与迁移：** 合入单节点 MinIO 迁移指南（[#228](https://github.com/pgsty/silo/pull/228)），校准运维默认参数说明，并将升级流程统一收敛至[迁移指南](/zh/compatibility/migration/)。

本版完整保留 [20261018](/zh/blog/release/silo-20261018/) 已交付的 Object Lock、IAM 授权、持久 STS 吊销、跨池迁移与 `LIST` 恢复修复。文末的依赖安全清单将本轮新合入的修复、历史修复与未使用代码中的扫描告警分别列出。

## mcli：自 20261018 以来的修改 {#mcli}

- **客户端身份缓存隔离（[#50](https://github.com/pgsty/mc/issues/50)、[#55](https://github.com/pgsty/mc/pull/55)）：** S3 与管理客户端缓存按凭据、证书信任、代理、DNS 解析器及自定义请求头隔离，同时保留凭据自动刷新与 Web Identity token 文件轮换。
- **复制 Resync 状态与速率计算（[#48](https://github.com/pgsty/mc/issues/48)、[#49](https://github.com/pgsty/mc/issues/49)、[#52](https://github.com/pgsty/mc/issues/52)）：** `admin replicate resync status --json` 会持续消费状态流直至到达 `Completed`、`Failed` 或 `Canceled` 终态，完整保留已完成任务的状态输出；当桶未启用复制时明确输出结果，TTY 模式在遇到 `Failed` 或 `Canceled` 时立即结束等待；同时修复了累计传输超过约 8.6 GiB 后吞吐量计算的整数溢出。
- **诚实的退出码（[#51](https://github.com/pgsty/mc/issues/51)）：** `resync start` 与 `resync cancel` 在部分桶操作失败时保留逐桶错误详情并返回非零退出码；用 `resync status` 成功查询到一个已处于 `Failed` 或 `Canceled` 状态的任务仍正常退出 `0`。`admin info --json` 在请求失败时同样返回非零退出码，并保留 JSON 错误输出。
- **批处理状态观察（[#53](https://github.com/pgsty/mc/issues/53)、[#54](https://github.com/pgsty/mc/issues/54)）：** `batch status` 在实时指标暂缺时继续观察并输出新增的 `pending` 状态（不再把排队中或缺样本的任务误判为已完成），在指标流中断时通过带超时边界的持久化状态查询兜底，并修复了超大对象计数下的 IOPs 整数溢出。
- **别名区域配置（[#44](https://github.com/pgsty/mc/pull/44)）：** 支持按 `MC_REGION`、`AWS_REGION`、持久别名配置中的 `region` 字段、自动发现的优先级解析区域，并在客户端缓存中隔离签名区域（未新增 `alias set --region` 命令行参数）。
- **底层 SDK 修复：** 拒绝被截短的顺序或并行分片读取流；修复 `ReadAt` 的 EOF 处理、负偏移校验及 `Stat` 之后的读取/Seek 边界；对批量删除回退路径中的重复错误去重；移除桶复制配置时同时接受 HTTP `200` 与 `204`（`403` 等真实鉴权或请求错误仍正常报错）。
- **打包与帮助信息（[#45](https://github.com/pgsty/mc/issues/45)）：** 升级至 Go 1.27.3 与 GoReleaser 2.19.0，Windows 归档改用 ZIP 格式；更新命令行帮助链接以及已停用的服务端自更新/SUBNET 命令提示，保留全部既有 CLI 配置与 `MC_*` 环境变量兼容。

自动化脚本请适配 `batch status` 新增的 `pending` 状态，以及 `resync start/cancel` 部分失败时的非零退出码。本次客户端升级无需变更服务端协议。下载流中途断开仍会立即报错；分片上传被 `SIGINT` 中断时以退出码 `130` 退出，未完成的分片可能需显式清理。详见[完整客户端提交历史](https://github.com/pgsty/mc/compare/RELEASE.2026-10-18T00-00-00Z...RELEASE.2026-10-26T00-00-00Z)。

## 升级与故障边界 {#upgrade}

1. **协调升级：** 升级前请备份 IAM 状态、配置文件与加密密钥，并按 [IAM 升级指南](/zh/operations/replication/iam-upgrade/)同步升级集群内的所有 Server 节点与跨站复制站点。不支持新旧版本进程长期共用同一 IAM 后端或执行滚动降级。
2. **升级后核验：** 逐一验证 LDAP/OIDC 登录、内置策略 Reset、存储桶清单刷新、多版本读取、跨站复制与加密对象解密。分片对象 `FULL_OBJECT` 校验和复制修复需要先升级发送端 Server，再检查待复制队列。
3. **归档格式与脚本适配：** Windows 平台归档已改为 `.zip`（Linux 与 macOS 保持 `.tar.gz`）；自动化脚本请适配 `mcli batch status` 的 `pending` 状态与 `resync start/cancel` 部分失败时的非零退出码。既有环境变量、配置文件名与磁盘存储格式保持不变。
4. **已知功能边界：** 公开的 `ListMultipartUploads` 仍使用节点本地内存缓存与精确对象键查找，已退役的 `strict` 开关会被忽略并打印警告；[#79](https://github.com/pgsty/silo/issues/79) 与 [#217](https://github.com/pgsty/silo/issues/217) 尚未关闭，Webhook 热重载 PR [#249](https://github.com/pgsty/silo/pull/249) 未纳入本版，更大范围的性能问题仍在 [#251](https://github.com/pgsty/silo/issues/251) 中跟踪。

**存储超时与一致性边界：** 客户端收到请求超时并不代表底层磁盘或 RPC I/O 已经停止，也不代表该次写入一定没有提交。在部分磁盘故障、锁租约过期或网络分区下，仍可能出现迟到提交、延迟回滚或短暂读到旧值与旧标签。本版未引入分布式锁 fencing，也不会自动恢复升级前已经损坏或丢失的对象、远端分层数据与元数据。

### Go 与证书信任 {#go-trust}

**[CVE-2026-111943 / GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809)**：Go 1.27.3 在 `crypto/x509` 证书链校验中直接拒绝已知失信的中间证书，在操作系统信任库尚未更新时也能提供兜底拦截。五个主项目及全部独立调试工具均统一使用 Go 1.27.3 编译。

此外，SILO、mcli 与 KES 的 UBI 容器信任库已应用 [Red Hat RHSB-2026-012](https://access.redhat.com/security/vulnerabilities/RHSB-2026-012) 的根证书封禁列表。由于根级封禁会一并拒绝挂靠在这些根证书之下的所有证书链，其拦截范围比 Go 1.27.3 的中间证书黑名单更广；若外部服务仍使用受影响根证书签发的证书链，需先行更换证书。发行版 CA 软件包的跟进状态见下文[本地缓解](#local-mitigations)。

## 已有历史修复，不属于本次新增漏洞 {#historical-findings}

按模块路径匹配的二进制扫描器仍会对 SILO 报告 **CVE-2025-27414、CVE-2026-33322、CVE-2026-33419、CVE-2026-34204、CVE-2026-39414、CVE-2026-40344、CVE-2026-41145、CVE-2026-42600**（因为 SILO 保留了 `github.com/minio/minio` 模块路径，而上游通告使用开放版本区间）。这八项缺陷在此前版本中均已修复并通过回归测试，详见 [SFTP 公告](https://pkg.go.dev/vuln/GO-2025-3495)、[OIDC](/zh/blog/security/cve-2026-33322/)、[LDAP](/zh/blog/security/cve-2026-33419/)、[复制元数据](/zh/blog/security/cve-2026-34204/)、[CSV](/zh/blog/security/cve-2026-39414/)、[Snowball](/zh/blog/security/cve-2026-40344/)、[签名校验](/zh/blog/security/cve-2026-41145/) 与 [ReadMultiple](/zh/blog/security/cve-2026-42600/)。

## 兼容性与依赖回归证据 {#compatibility}

为避免已复现的终端表格输出变化、字符宽度计算差异及 NetBSD 交叉编译回归，本次固定保留 `tablewriter 0.0.5`、`go-humanize 1.0.1`、根模块 `go-runewidth 0.0.29` 及 `go-systemd/v22 22.6.0`（`xattr` 模块保留其既有宽度库组合）。此外：
- Kafka 通知目标在应用用户配置前显式保留协议版本默认值 `2.1`；
