**状态：已在本地准备，尚未发布。** 计划标签为 `RELEASE.2026-10-25T00-00-00Z`，软件包版本为 `20261025000000.0.0`。当前正式版仍为 [KES 20261018](/zh/blog/release/kes-20261018/)。制品、签名与容器摘要将在发布后补充；[下载页](/zh/download/#kes) 继续指向已发布版本。

KES 是可选、独立发布的服务。本候选属于 [10 月 25 日维护批次](/zh/blog/release/silo-20261025/)，KES 的发布不代表 SILO Server 或 Console 已完成发布验收。

## 工具链与依赖 {#dependencies}

相较 KES 20261018，候选将 Go 从 **1.27.2 升至 1.27.3**，更新 **25 个声明依赖模块**。这些依赖改动此前已经提交至 KES 的 `main` 分支；本次发布准备对其复验，并纳入 Windows ZIP 归档改动。

| 依赖 | 已发布 KES 20261018 | 候选版本 |
| --- | --- | --- |
| AWS SDK v2 核心 | 1.47.3 | **1.47.4** |
| AWS SDK config / credentials | 1.33.9 / 1.20.9 | **1.33.10 / 1.20.10** |
| AWS Secrets Manager | 1.50.4 | **1.50.6** |
| Google Secret Manager | 1.22.0 | **1.23.0** |
| Google API / IAM | 0.304.0 / 1.14.0 | **0.308.0 / 1.15.0** |
| Google certificate proxy / GAX | 0.3.23 / 2.26.2 | **0.3.24 / 2.27.0** |
| HashiCorp go-rootcerts | 1.0.2 | **1.1.0** |
| Prometheus procfs | 0.22.0 | **0.23.0** |

其余更新包括 AWS 配套模块与三个 Google 生成 API 模块。10 月 25 日检查了全部 **26 个直接依赖、76 个间接依赖**，以及选定模块图中的另外 93 个模块。所有声明依赖均已达到 Go 在其现有模块路径下选出的最新版本。仅出现在模块图中、未被 KES 及其测试导入的模块，由所属上游依赖推进。

Lip Gloss v1 与 `gopkg.in/yaml.v3` 保留既有兼容版本。迁移至 Lip Gloss v2 或维护中的 YAML 导入路径，需要单独完成终端输出及配置迁移验证。本版不改变 KES HTTP API、配置结构或已存密钥格式。

## 安全与打包 {#security}

Go 1.27.3 包含[共享安全说明](/zh/blog/release/silo-20261025/#go-trust)中的证书验证修复。容器更新 UBI 9.8 基础镜像摘要，并采用此前记录的根证书阻断列表。这一信任库缓解范围更广，仍使用被阻断根证书链的服务可能连接失败，详见[共享证书说明](/zh/blog/release/silo-20261025/#local-mitigations)。

使用 govulncheck 1.9.0 对 Linux、macOS、Windows 进行源码扫描，均未发现受影响的已导入包。`golang.org/x/crypto` 中未使用的 OpenPGP 包仍有模块级 `GO-2026-5932` 记录；这不代表整个模块图或容器镜像没有漏洞。系统包限制见[共享 UBI 说明](/zh/blog/release/silo-20261025/#ubi-residuals)。

发布流水线将 GoReleaser 从 **2.18.3 升至 2.19.0**，其[发行说明](https://github.com/goreleaser/goreleaser/releases/tag/v2.19.0)包含 Go 1.27.3、依赖安全更新及归档错误处理修复。nFPM 保持当前的 **2.48.0**，CI 使用 `go.mod` 指定的 Go 工具链构建。

Linux 与 macOS 归档继续使用 `.tar.gz`，Windows 归档改用 `.zip`。计划继续提供六个平台归档及六个 Linux RPM/DEB/APK 软件包，校验文件、RPM 签名及 GitHub 构建证明沿用现有发布流程。软件包安装 `/usr/local/bin/kes`，不会启动尚未配置的服务。

## 发布验收 {#validation}

候选已通过本地 Go 全量 race 测试、vet、lint、模块完整性与 tidy 检查、品牌检查及发布保护脚本测试。云后端测试覆盖本地协议模拟，包括 Secret Manager 操作与分页；不等同于真实云账号认证。

使用 GoReleaser 2.19.0 从同一个干净提交构建了六个平台归档和六个 Linux 软件包，归档校验值、包元数据、二进制内容及许可证文件均已核对。两个 Linux 容器架构均以 UID/GID `1000:1000` 成功运行，下述 OpenBao/Moto 与三个 SILO 版本的六种组合均通过升级、回退和冷读回。这些产物仍是本地快照：RPM 尚未签名，候选也尚无托管发布流程生成的构建证明。

发布矩阵加入 SILO **20261018、20260916、20260903**。OpenBao 升级验收以已发布 PGSTY KES 20261018 二进制为起点，先用 GitHub 构建证明核对归档和校验清单。Moto Secrets Manager 验收继续使用 PGSTY 的 AWS SDK v1 基线。两组流程均覆盖升级、回退和重启，每次版本切换都重启 SILO，清除密钥缓存。原版上游 KES 的升级兼容性保留为独立、尽力支持的参考检查。

KES 的远端默认分支及发布分支仍是 `master`，依赖升级目前在 `main`。正式发布需要将候选合入 `master`，等待四项必需工作流对该提交的 push 运行全部成功，再构建和审查签名标签对应的制品。GitHub Release 与 Docker Hub 镜像分别发布。
