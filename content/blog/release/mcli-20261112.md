**mcli 20261112 is released.** Tag: [`RELEASE.2026-11-12T00-00-00Z`](https://github.com/pgsty/mc/releases/tag/RELEASE.2026-11-12T00-00-00Z); package version: **`20261112000000.0.0`**; source: [`a37a9f054fba`](https://github.com/pgsty/mc/commit/a37a9f054fba828a0bbbceb4e9ff247ccf09c28d). These notes cover changes since [mcli 20261109](/blog/release/mcli-20261109/).

This is a standalone mcli maintenance release. [Console 2.7.1](/blog/release/console-2.7.1/) adopts this exact release commit (`v0.0.0-20261111180825-a37a9f054fba`), while published [SILO Server 20261109](/blog/release/silo-20261109/) retains `mcli 20261109` until the next Server release is published. The maintained target is **PGSTY SILO**; upstream MinIO and other S3-compatible services remain best effort.

## Policy validation and inline-policy reset {#policy}

- **Explicit empty inline-policy reset ([pgsty/mc#78](https://github.com/pgsty/mc/issues/78)):** `admin accesskey edit --policy`, `idp ldap accesskey edit --policy`, and `idp openid accesskey edit --policy` now accept an explicit empty policy document (`{}` or `{"Statement":[]}`), matching `admin user svcacct edit --policy` and `admin user svcacct set`. When paired with a SILO Server containing the post-`20261109` service-account policy fix ([`SN-2026-021`](/about/security-advisories/#sn-2026-021)), passing an explicit empty document clears the inline session policy and restores inheritance from the parent user, whereas omitting `--policy` preserves the existing inline policy. Updating the client binary alone does not change an older Server's behavior.
- **Strict policy JSON validation:** adopts [silo-pkg v3.16.1](/blog/release/pkg-3.16.1/) so client-side IAM and bucket policy parsing rejects unknown JSON fields, trailing payloads, non-object documents, empty `Principal: {}` blocks, and unsupported `NotPrincipal` clauses instead of silently dropping them. Account creation and named-policy writes continue to reject empty policy documents.
