**Status: prepared locally, not released.** The planned tag is `RELEASE.2026-10-25T00-00-00Z`, with package version `20261025000000.0.0`. The current published version remains [KES 20261018](/blog/release/kes-20261018/). Release assets, signatures and container digests will be recorded after publication; the [download page](/download/#kes) continues to point to the published version.

KES is an optional, independently released service. This candidate belongs to the [October 25 maintenance batch](/blog/release/silo-20261025/); releasing KES does not establish release readiness for SILO Server or Console.

## Toolchain and dependencies {#dependencies}

Compared with KES 20261018, the candidate raises Go from **1.27.2 to 1.27.3** and updates **25 required modules**. The dependency changes were already committed to the KES `main` branch; this release preparation verifies them and brings them together with the Windows ZIP packaging change.

| Dependency | Published KES 20261018 | Candidate |
| --- | --- | --- |
| AWS SDK v2 core | 1.47.3 | **1.47.4** |
| AWS SDK config / credentials | 1.33.9 / 1.20.9 | **1.33.10 / 1.20.10** |
| AWS Secrets Manager | 1.50.4 | **1.50.6** |
| Google Secret Manager | 1.22.0 | **1.23.0** |
| Google API / IAM | 0.304.0 / 1.14.0 | **0.308.0 / 1.15.0** |
| Google certificate proxy / GAX | 0.3.23 / 2.26.2 | **0.3.24 / 2.27.0** |
| HashiCorp go-rootcerts | 1.0.2 | **1.1.0** |
| Prometheus procfs | 0.22.0 | **0.23.0** |

The remaining updates are AWS supporting modules and the three Google generated API modules. An October 25 audit checked all **26 direct and 76 indirect requirements**, along with the additional 93 modules in the selected module graph. All declared requirements already match the latest versions selected by Go for their existing module paths. Graph-only modules that KES and its tests do not import are left to their owning dependencies.

Lip Gloss v1 and `gopkg.in/yaml.v3` remain at their existing compatible versions. Moving to Lip Gloss v2 or the maintained YAML import path requires separate output and configuration migration validation. This release does not change the KES HTTP API, configuration schema or stored key format.

## Security and packaging {#security}

Go 1.27.3 includes the certificate-verification fix described in the [shared security notes](/blog/release/silo-20261025/#go-trust). The container uses refreshed UBI 9.8 base digests and the previously documented root certificate blocklist. This broader trust-store mitigation can reject services whose certificates still chain to the blocked roots; see the [shared certificate notes](/blog/release/silo-20261025/#local-mitigations).

Source scans with govulncheck 1.9.0 for Linux, macOS and Windows found no affected imported packages. `GO-2026-5932` remains a module-level finding for unused OpenPGP packages in `golang.org/x/crypto`; this is not a claim that the module graph or container image has no vulnerabilities. System-package limitations are tracked in the [shared UBI notes](/blog/release/silo-20261025/#ubi-residuals).

The release pipeline upgrades GoReleaser from **2.18.3 to 2.19.0**, whose [release notes](https://github.com/goreleaser/goreleaser/releases/tag/v2.19.0) include Go 1.27.3, dependency security updates and archive error handling fixes. nFPM remains at the current **2.48.0**; CI builds it with the Go toolchain from `go.mod`.

Linux and macOS archives remain `.tar.gz`; Windows archives become `.zip`. The planned distribution remains six platform archives and six Linux RPM/DEB/APK packages, with checksums, signed RPMs and GitHub provenance following the existing release process. The package installs `/usr/local/bin/kes` without starting an unconfigured service.

## Release checks {#validation}

The candidate passes the local full Go race suite, vet, lint, module integrity/tidiness checks, branding checks and release guard tests. Cloud tests cover local protocol fixtures, including Secret Manager operations and pagination; they do not certify live cloud accounts.

Local GoReleaser 2.19.0 builds produced all six platform archives and six Linux packages from one clean commit. Archive checksums, package metadata, binary payloads and license files were verified, and both Linux container architectures ran successfully as UID/GID `1000:1000`. All six OpenBao/Moto and SILO-version combinations below passed upgrade, rollback and cold readback. These are local snapshots: the RPMs are unsigned and the candidate has no hosted release attestations yet.

The release matrix now includes SILO **20261018, 20260916 and 20260903**. OpenBao upgrade checks start from the published PGSTY KES 20261018 binary, verifying its archive and checksum manifest against GitHub attestations. The Moto Secrets Manager checks retain the PGSTY AWS SDK v1 baseline. Both fixtures exercise upgrades, rollback and restart, restarting SILO at each transition to discard cached keys. Upgrade from unmodified upstream KES remains a separate best-effort advisory check.

KES still uses `master` as its remote default and release branch, while the dependency updates are on `main`. Publication requires merging the candidate into `master`, successful push-triggered runs of all four required workflows for that exact commit, then signed-tag artifact construction and review. GitHub Release and Docker Hub publication are separate steps.
