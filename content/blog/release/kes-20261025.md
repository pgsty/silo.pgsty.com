**KES 20261025000000 is released.** The [GitHub release](https://github.com/pgsty/kes/releases/tag/RELEASE.2026-10-25T00-00-00Z) uses tag `RELEASE.2026-10-25T00-00-00Z`, package version `20261025000000.0.0`, and source [`b0a98d87f656`](https://github.com/pgsty/kes/commit/b0a98d87f6564c1a6d9584c0a5260910a731f66d). This October 25 maintenance version was published on October 26. The [download page](/download/#kes) points to its archives and packages. The matching Docker Hub image is published for `linux/amd64` and `linux/arm64`; the version tag and `latest` select the same verified image.

KES is an optional, independently released service. This release belongs to the [October 25 maintenance batch](/blog/release/silo-20261025/); releasing KES does not establish release readiness for SILO Server or Console.

## Toolchain and dependencies {#dependencies}

Compared with KES 20261018, this release raises Go from **1.27.2 to 1.27.3** and updates **25 required modules**. The dependency changes were already committed to the KES `main` branch; this release preparation verifies them and brings them together with the Windows ZIP packaging change.

| Dependency | Published KES 20261018 | 20261025 |
| --- | --- | --- |
| AWS SDK v2 core | 1.47.3 | **1.47.4** |
| AWS SDK config / credentials | 1.33.9 / 1.20.9 | **1.33.10 / 1.20.10** |
| AWS Secrets Manager | 1.50.4 | **1.50.6** |
| Google Secret Manager | 1.22.0 | **1.23.0** |
| Google API / IAM | 0.304.0 / 1.14.0 | **0.308.0 / 1.15.0** |
| Google certificate proxy / GAX | 0.3.23 / 2.26.2 | **0.3.24 / 2.27.0** |
| HashiCorp go-rootcerts | 1.0.2 | **1.1.0** |
| Prometheus procfs | 0.22.0 | **0.23.0** |

The remaining updates are AWS supporting modules and the three Google generated API modules. The October 25 audit and October 26 rescan checked all **26 direct and 76 indirect requirements**, along with the additional 93 modules in the selected module graph. All declared requirements already match the latest versions selected by Go for their existing module paths. Graph-only modules that KES and its tests do not import are left to their owning dependencies.

Lip Gloss v1 and `gopkg.in/yaml.v3` remain at their existing compatible versions. Moving to Lip Gloss v2 or the maintained YAML import path requires separate output and configuration migration validation. This release does not change the KES HTTP API, configuration schema or stored key format.

## Security and packaging {#security}

Go 1.27.3 includes the `crypto/x509` certificate-verification fix for **CVE-2026-111943 / GO-2026-6809**, described in the [shared security notes](/blog/release/silo-20261025/#go-trust). The container recipe uses refreshed UBI 9.8 base digests and the previously documented root certificate blocklist. This broader trust-store mitigation can reject services whose certificates still chain to the blocked roots; see the [shared certificate notes](/blog/release/silo-20261025/#local-mitigations).

Source scans with govulncheck 1.9.0 for Linux, macOS and Windows found no affected imported packages. `GO-2026-5932` remains a module-level finding for unused OpenPGP packages in `golang.org/x/crypto`; this is not a claim that the module graph or container image has no vulnerabilities. System-package limitations are tracked in the [shared UBI notes](/blog/release/silo-20261025/#ubi-residuals).

The release pipeline upgrades GoReleaser from **2.18.3 to 2.19.0**, whose [release notes](https://github.com/goreleaser/goreleaser/releases/tag/v2.19.0) include Go 1.27.3, dependency security updates and archive error handling fixes. nFPM remains at the current **2.48.0**; CI builds it with the Go toolchain from `go.mod`.

Linux and macOS archives remain `.tar.gz`; Windows archives become `.zip`. The distribution provides six platform archives and six Linux RPM/DEB/APK packages, with checksums, signed RPMs and GitHub provenance following the existing release process. The package installs `/usr/local/bin/kes` without starting an unconfigured service.

## Release checks {#validation}

Source [`b0a98d87f656`](https://github.com/pgsty/kes/commit/b0a98d87f6564c1a6d9584c0a5260910a731f66d) passed the required push-triggered [Go](https://github.com/pgsty/kes/actions/runs/40257613627), [VulnCheck](https://github.com/pgsty/kes/actions/runs/40257613658), [KMS Compatibility](https://github.com/pgsty/kes/actions/runs/40257613681), and [Test Release Pipeline](https://github.com/pgsty/kes/actions/runs/40257613626) workflows before tagging. Local full Go race tests, vet, lint, module integrity/tidiness, branding and release guard checks also passed. Cloud tests use local protocol fixtures; they do not certify live AWS, GCP or Azure accounts.

The [Release workflow](https://github.com/pgsty/kes/actions/runs/40258161919) provides six platform archives and six Linux packages, with 19 downloadable files including checksums. The release tag and both RPMs are signed with the Pigsty OpenPGP key; GitHub build attestations cover the archives, archive checksum manifest, DEBs and APKs. Downloaded binary versions, clean source stamps, dependency versions, package payloads and license files were verified before publication.

The maintained compatibility matrix covers OpenBao KV v2 and Moto Secrets Manager with SILO **20261018, 20260916 and 20260903**. OpenBao checks start from the published PGSTY KES 20261018 binary after verifying its archive and checksum manifest against GitHub attestations. Moto checks retain the PGSTY AWS SDK v1 baseline. Both fixtures exercise upgrade, rollback and restart, restarting SILO at every transition to discard cached keys. Upgrade from unmodified upstream KES remains advisory.

The downloaded KES release binary also passed both backend fixtures with the actual **SILO 20261025 Draft** and released **mcli 20261025** binaries. Objects written before and after upgrading decrypted after rollback and cold server restarts; the stored keys survived test cleanup. These local checks cover protocol and version compatibility, not backend crash durability.

KES keeps `master` as its default release branch, with the same source synchronized to `main`. GitHub Release and Docker Hub are separate deliverables. This KES release does not publish SILO Server or change its storage-consistency limits.
