**已于 2026-10-25 正式发布。** 签名 Git 标签为 [`RELEASE.2026-10-25T00-00-00Z`](https://github.com/pgsty/mc/releases/tag/RELEASE.2026-10-25T00-00-00Z)，软件包版本为 `20261025000000.0.0`。[下载页](/zh/download/#client)提供跨平台归档、Linux 软件包与 Docker 镜像。本客户端属于 [20261025 统一维护批次](/zh/blog/release/silo-20261025/)。

## 相对 20261018 的变更 {#changes}

- 采用 **Go 1.27.3** 与 **silo-pkg v3.15.1**，保留共享包的策略判定优化与既有授权语义，刷新 Prometheus、etcd、gRPC、JWX、JSON 和终端依赖。Go 证书信任修复及发行容器根证书阻止列表见[统一维护公告](/zh/blog/release/silo-20261025/#go-trust)。
- 升级上游 **minio-go `v7.4.2-0.20261020194015-ab93db7ba435`**（v7.4.1 之后的固定上游提交）：顺序与并行分段上传遇到截短输入时立即返回失败，避免提交截短对象；单对象删除回退失败只报告一次错误；同时修复 `ReadAt` 的 EOF 与负偏移处理，以及 `Stat` 之后的读取与 `Seek` 边界（并行 SDK GET 仍需显式启用）。
- 支持别名配置中持久化的可选 `region` 字段，解析优先级为 `MC_REGION`、`AWS_REGION`、别名配置；未设置时自动查询存储桶所在区域。客户端缓存按签名区域隔离。本次未新增 `alias set --region` 命令行参数。
- `admin info --json` 失败时返回**非零退出码**，同时保留原有 JSON 错误输出（20261018 在权限被拒绝时输出 `status: error` 但仍返回零退出码）。
- Windows `amd64` 与 `arm64` 归档改用 **ZIP** 格式；Linux 与 macOS 保持 **tar.gz**。发布检查覆盖归档格式、随包文档、校验和与二进制源码标记。
- 更新已禁用的服务端自更新与 SUBNET 命令说明，完善 SQL 示例和 SILO 帮助链接。CI 功能测试固定采用 SILO 20261018 校验和制品。

## 升级注意事项 {#upgrade}

配套维护与验收的服务端为 **pgsty/silo**，对上游 MinIO 及其他 S3 服务提供尽力兼容。本次客户端更新无需同步升级 Server 或 Console。

既有 CLI 配置文件与 `MC_*` 环境变量保持兼容；保留 `go-systemd v22.6.0`（NetBSD 兼容）、`go-runewidth v0.0.29`（终端列宽计算）及 `tablewriter v0.0.5` API。自动拉取 Windows 归档的脚本从本版本起需改为下载 `.zip`。

CLI 分段上传被 `SIGINT` 中断时退出码为 `130`，不会暴露未完成的对象，但可能残留已上传分片（与 20261018 一致），可按需清理对应前缀：

```sh
mcli rm --incomplete --recursive --force ALIAS/BUCKET/PREFIX
```

下载响应体中途断开时命令会直接报错退出，请重新执行下载。

## 验收与交付状态 {#validation}

本机验收覆盖最新 SILO 源码与已发布的 20261018 服务端（单节点四数据目录），包含 HTTP 与可信 TLS 下的 Go/Shell 功能套件、SSE-S3/SSE-C/专用测试 KMS 密钥、版本控制、Object Lock、复制、IAM、STS、失败复制的源文件保护、部分镜像失败、持续镜像（watch）历史、SQL 及网络故障恢复。全量单元测试（含 `-race`）、静态检查、漏洞扫描与全部 262 个可见命令帮助页均通过。文件属性保留用例对比读取前的快照，覆盖 Linux 读取上传源文件触发 `atime` 更新的场景。六个归档、六个 Linux 软件包与两种 Linux 容器架构均通过本地检查，且六种 Linux 软件包均完成 20261018 安装、升级至 20261025、回滚与卸载测试（保留客户端配置）。本机执行覆盖原生 macOS arm64、Linux arm64 与模拟 Linux amd64；GitHub 托管 CI 通过原生 Windows amd64、macOS arm64 与 Linux amd64 测试，并完成 Windows arm64 与 macOS amd64 交叉编译验证。

发行源码为 [`dcc78d506f94`](https://github.com/pgsty/mc/commit/dcc78d506f94e7c2323b642d48fbb600664f0586)。签名标签已固定在该提交，最终制品由 GitHub [Release 工作流](https://github.com/pgsty/mc/actions/runs/40187476316)构建。

**发布门禁（4/4 通过）：** [Go](https://github.com/pgsty/mc/actions/runs/40186055887)、[Crosscompile](https://github.com/pgsty/mc/actions/runs/40186055839)、[VulnCheck](https://github.com/pgsty/mc/actions/runs/40186055833) 与 [Test Release Pipeline](https://github.com/pgsty/mc/actions/runs/40186055892) 在合入 `main` 时全部通过，且发布门禁已核验标签指向 `main` 最新提交。

## 正式制品 {#delivery}

[GitHub Release](https://github.com/pgsty/mc/releases/tag/RELEASE.2026-10-25T00-00-00Z) 提供 **19 个文件**：六个跨平台归档、六个 Linux 软件包、归档校验和清单及六个软件包校验和文件。19 个文件均已通过匿名下载与最终 SHA-256 核验。六个归档中的二进制均带有上述发行提交标记，各软件包内的程序与对应 Linux 归档一致。

两个 RPM 均由 PGSTY 密钥 `9592A7BC7A682E7333376E09E7935D8DB9BD8B20` 签名并通过验签（[公钥](https://github.com/Vonng.gpg)）。**11 份 GitHub 构建证明**均已按本次标签、提交、文件名、摘要和托管 Release 工作流核验，覆盖六个归档、归档校验和清单、两个 DEB 和两个 APK。RPM 签名会在构建后改变包字节，因此由 GPG 签名保证完整性。

[Docker 发布工作流](https://github.com/pgsty/mc/actions/runs/40188250063)已将 **linux/amd64** 与 **linux/arm64** 镜像发布至 [Docker Hub](https://hub.docker.com/r/pgsty/mc)。两个架构均已重新拉取并运行，镜像内程序与公开 Linux 归档一致，OCI 版本与源码标记正确，许可证文件和证书阻止列表也已核验。版本标签与 `latest` 指向同一多架构摘要：

```text

sha256:770d5f14a70ecb88e0086d3a8061de726309bee986298fef06f09429fdd683cf
```

可使用版本标签选择明确版本，或按索引摘要固定镜像：

```sh
docker run --rm docker.io/pgsty/mc@sha256:770d5f14a70ecb88e0086d3a8061de726309bee986298fef06f09429fdd683cf --version
```

各平台与软件包格式见[下载与安装](/zh/download/#client)。Windows 归档使用 ZIP，Linux 与 macOS 继续使用 tar.gz。
