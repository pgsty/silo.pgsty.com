## S3、复制与 Object Lock 安全收口 {#authorization}

- **单池 `DeleteObjects` 路径隔离（[SN-2026-020](/zh/blog/security/20261110-bulk-delete-path-traversal/)）：** 单存储池 `DeleteObjects` 在下发磁盘前拦截未通过对象名合法性检查（如含 `..` 路径段）的条目并返回 `XMinioInvalidObjectName`，防止跨桶删除、`.minio.sys` 元数据写入及 `COMPLIANCE` 对象锁绕过（`a18293d0c`）。
- **双活复制标签与读取代理（[SN-2026-022](/zh/blog/security/20261111-tagging-replication-proxy-auth/)，[#337](https://github.com/pgsty/silo/issues/337)）：** `DeleteObjectTagging` 在转发复制代理前先完成认证；`GetObjectTagging`、`PutObjectTagging`、`DeleteObjectTagging` 与代理 `GET`/`HEAD` 均读取并校验远端存量标签（`14ecb222e`、`67a90dfef`、`293ab78b4`、`c39605d4f`），对不可读目标失败关闭并容忍复制延迟导致的缺失副本；本地与复制代理 `GET`/`HEAD` 仅在调用方具备未被显式拒绝的对应标签或保留期／法务保留读取权限时才返回 `x-amz-tagging-count`、`X-Amz-Tagging` 及规范大小写 `X-Amz-Object-Lock-*` 响应头（`ea37a7e8b`）。
- **SigV4 与流式尾标认证（[SN-2026-023](/zh/blog/security/20261111-streaming-unsigned-trailer-replay/)，[#338](https://github.com/pgsty/silo/issues/338)）：** 已认证的 `STREAMING-UNSIGNED-PAYLOAD-TRAILER` 分块上传强制校验 15 分钟签名时间窗与 `checkUnsignedHeaders` 请求头覆盖，同时保留桶策略授权的匿名上传（`14ecb222e`、`296c9710b`）；拒绝 SigV4 凭据作用域日期与请求时间戳不符、负数 `X-Amz-Decoded-Content-Length` 及截断或超过 64 KiB 的流式尾标。
- **存量标签与指定版本鉴权（[SN-2026-024](/zh/blog/security/20261111-attributes-and-archive-tag-authz/)，[#293](https://github.com/pgsty/silo/issues/293)，[#342](https://github.com/pgsty/silo/issues/342)）：** 在 `GetObjectAttributes`、`CopyObject`、`UploadPartCopy`、`SelectObjectContent` 以及纯内存无写入副作用的 ZIP 归档成员读取／列举（`s3:ListBucket` + `s3:GetObject`）上强制校验 `s3:ExistingObjectTag/<key>`；带标签条件 `GET`/`HEAD` 未达读仲裁时保留 `5xx` 存储错误；`CopyObject` `COPY` 标签指令按实际复制标签评估目的端请求标签条件；带 `versionId` 的读取与标签操作优先执行版本动作的显式 `Deny`，无显式版本拒绝时保留历史基础动作兼容授权。
- **副本与 `null` 版本 Object Lock（[#336](https://github.com/pgsty/silo/issues/336)）：** 副本写入与复制在修改锁内合并目标端锁与标签状态，提交前核验暂存副本哈希、SSE-C 状态与压缩前 `ActualSize`，阻止对端时间戳清除或缩短未到期 `COMPLIANCE` 合规保留期，要求 `X-Minio-Replication-*` 请求头纳入基于请求头的 SigV4 签名，在 `x-minio-force-delete` 无法读取桶锁元数据时失败关闭（`cf486df66`），并在暂停版本控制或前缀排除的存储桶中跨单池与多池部署保护受锁 `null` 版本免遭普通覆写、删除标记或无版本 `DELETE` 破坏。

## IAM、服务账号与严格策略校验 {#iam-policy}

- **服务账号三态内联策略语义（[SN-2026-021](/zh/blog/security/20261110-svcacct-inline-policy-preservation/)、[SN-2026-025](/zh/blog/security/20261111-iam-import-status-and-console-policy/)，[#331](https://github.com/pgsty/silo/pull/331)，[#339](https://github.com/pgsty/silo/issues/339)，[#345](https://github.com/pgsty/silo/issues/345)）：** `UpdateServiceAccount` 在 `newPolicy` 省略或为 `null` 时保留既有内联会话策略（含 `20261111` 前历史全拒绝空 `embedded-policy` 账号），仅在收到显式空策略文档（`{}` 或 `{"Statement":[]}`）时清除内联限制并恢复父账号继承，并为缺少 `Version` 的非空内联策略自动补齐 `2012-10-17`。IAM 导入完整保留服务账号与用户组的禁用状态并准确报告组导入错误（`1d714834c`）。
- **严格策略 JSON 解码：** IAM 命名策略、服务账号会话策略、STS `Policy` 参数、IAM 导入／复制与存储桶策略统一通过 [silo-pkg v3.16.1](/zh/blog/release/pkg-3.16.1/) 拒绝未知 JSON 字段、尾部多余 token、非对象输入、空 `Principal: {}` 及未实现的 `NotPrincipal`（`34ba7cc1f`），导入前先完整校验策略归档，同时保持存量落盘 IAM 策略读取与桶策略复制显式 `null` 删除墓碑兼容。
- **站点复制并发锁快照与凭据清理：** IAM 自愈、存储桶与元数据自愈、状态采集及复制钩子均先获取站点拓扑快照并释放集群状态锁后再执行存储读写与对端 RPC（见[设计说明](/zh/blog/design/site-replication-lock-snapshots/)），导出与复制凭据自动剥离派生策略声明。

## 存储池、压缩加密区间读取、生命周期与批处理 {#storage}

- **跨池复制与迁移池权威副本（[#343](https://github.com/pgsty/silo/issues/343)）：** 历史版本自身复制（向同名 key 发起 `PUT ?versionId=...`）可在多存储池集群中为明文、SSE-S3、SSE-KMS、SSE-C 及多块 S2 压缩对象（保留 `Parts[0].Index` 寻址索引）生成可读新版本；原地副本元数据更新在退役或再平衡池上保留权威正文（见[设计说明](/zh/blog/design/multi-pool-copy-placement/)）。
- **压缩加密对象 `Range` 读取：** 同时启用压缩与服务端加密（`SSE-S3`、`SSE-KMS`、`SSE-C`）的对象在执行带索引字节区间读取时，即使目标压缩分块起点位于首个 64 KiB 加密帧内部（`decryptSkip > 0`），也能准确推进 DARE 解密流而无需重写存量对象，同时在底层密文篡改损坏时继续严格验签失败关闭（`939cb2600`）。
- **生命周期／恢复版本仲裁与元数据缓存（[#332](https://github.com/pgsty/silo/pull/332)，[#344](https://github.com/pgsty/silo/issues/344)）：** 统一规范化 `2024-04-28` 前部分自愈遗留的旧 `xl.meta` 头部（见[设计说明](/zh/blog/design/lifecycle-history-old-headers/)），并从 `revisionKey` 比对中清除随时间变化的 `xlFlagUsesDataDir` 标志位，避免拆散跨盘仲裁；`BucketMetadataSys.GetConfig` 防止旧缓存覆盖较新的存储桶配置。
- **存储池退役（[#334](https://github.com/pgsty/silo/issues/334)）：** 停止无实质物理进展的空转扫描、及时返回取消错误、重新扫描此前被精确同名父对象遮蔽的子键，并在核验源端清理时容忍纠删集读仲裁范围内的离线磁盘。
- **SSE-KMS 加密上下文与批处理密钥轮换：** S3 写入接口（`PutObject`、`CopyObject`、`CreateMultipartUpload`、表单 `POST`）对空值、畸形 Base64/UTF-8/JSON、尾随 token 或非字符串／非 `null` 成员值的 `X-Amz-Server-Side-Encryption-Context` 请求头统一返回 `400 InvalidArgument`（不再返回 `500 InternalError`）。Batch `keyrotate` 在执行、重试与清单重载全链路保留已配置的 KMS 上下文（见[设计说明](/zh/blog/design/batch-keyrotate-kms-context/)），将历史 `XLV1` 对象流式重写为带明文 MD5 密封 ETag 且保留标签／过期时间的 `XLV2` 对象，并在 `SSE-S3` 转 `SSE-KMS` 时保留内部分片与分层头。

## 升级与回滚 {#upgrade}

1. **重启前确认 `.minio.sys` 读仲裁健康，并保留 20261109 升级前提。** 重启前核实各纠删集具备健康读仲裁。若从 `20261026` 及更早版本直接跨版本升级，须同时遵循 [20261109 升级清单](/zh/blog/release/silo-20261109/#upgrade)（排空或取消未完成 Batch 作业；单池各纠删集未共享相同主机集合时——如 18 台及以上自动布局主机——须全量停机切换；混合版本期间暂停 `POST ?restore`）。
2. **多存储池集群跨版本滚动重启期间排空或暂停并发 S3 写入。** 在全部节点运行 `20261112` 前，新旧节点混跑可能交错多池写锁顺序或在未升级对端跳过挂起／前缀排除桶的 `null` 版本对象锁检查。
3. **多站点滚动升级窗口内冻结未升级 `20261109` 站点的服务账号编辑。** 在 `20261109` 及更早站点上切换状态或无 `--policy` 修改属性仍会剥离内联会话策略并同步至对端。待全部站点升至 `20261112` 后，按经人工复核的目标策略核查 `mcli admin user svcacct info` 显示 `Policy: implied` 的账号，切勿盲目执行 `site-replication resync`。
4. **上线前排查自动化脚本中的策略与加密上下文 JSON 格式。** 提交拼写错误策略键（如误写 `Conditions`）、尾随 JSON、空 `Principal: {}`、`NotPrincipal` 或非字符串 KMS 加密上下文值的自动化调用现在会收到 `400`，不再静默丢弃字段或返回 `500`。
5. **重启后逐节点验证 S3 数据路径并显式指定 Helm 镜像标签。** 对每个重启节点执行有界超时的签名 S3 写入与回读校验；以 `--reuse-values` 升级 Helm Chart `7.0.5` 时，显式传入 `--set image.tag=RELEASE.2026-11-12T00-00-00Z`。

## 代价与限制 {#limits}

S3 `DeleteObjects` 中所有显式指定 `VersionId` 的版本删除（包括未启用 Object Lock 的普通存储桶）以及可能替换受锁 `null` 版本的无版本删除，现在统一走单对象顺序执行路径，大批量显式版本清理耗时相应增加；普通删除标记写入与不涉及受锁 `null` 版本的无版本批量删除继续走并发批量路径。

存储超时仍不证明底层磁盘写入未提交，本版本不新增分布式 fencing，也不会自动恢复历史已删除数据或已被剥离的内联策略。已知限制仍包括 `ListMultipartUploads` 前缀与分页（[#79](https://github.com/pgsty/silo/issues/79)）、多站点删除标记清除（[#217](https://github.com/pgsty/silo/issues/217)）、站点复制重放建桶（[PR #241](https://github.com/pgsty/silo/pull/241)），以及上游 SDK 在分片完成重试时可能丢失条件请求头（`mcli put --if-not-exists`；见[分片完成重试分析](/zh/blog/design/multipart-complete-retry/)）。
