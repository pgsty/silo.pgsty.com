**暂定日期：** 2026-08-24 · **候选版本：** `RELEASE.2026-08-24T00-00-00Z` · **状态：** 草稿

本候选版本将 `pgsty/mc` 客户端升级至 Go 1.27.0，与当前 SILO 服务端对齐共享依赖栈，修复 Prometheus Metrics JSON 输出中一处历史 panic，并为所有发行格式提供确定、完整的第三方许可证清单。命令名、参数、配置路径与格式、软件包命名，以及 S3/Admin 线协议均保持不变。

## 工具链与 Go 模块 {#toolchain}

- 模块声明、容器构建阶段、Linux/macOS/Windows CI、交叉构建、tidy 校验与漏洞扫描全部统一为 **Go 1.27.0**。
- 本地最低构建版本明确为 Go 1.27.0；由于 Go 1.27 不再支持 macOS 12 及更早版本，macOS 构建下限同步调整为 13.0。
- Go 官方扩展模块更新至当前版本：`x/net` 0.58.0、`x/sys` 0.47.0、`x/term` 0.45.0、`x/text` 0.41.0、`x/crypto` 0.55.0、`x/mod` 0.40.0、`x/sync` 0.22.0、`x/tools` 0.49.0。
- `golangci-lint` 不再进入产品模块图，而是通过 Go proxy/sumdb 按固定的 `v2.13.1` 独立安装。

## SILO 依赖栈对齐 {#dependency-alignment}

- `github.com/minio/pkg/v3` 现在解析到持续维护的 [`github.com/pgsty/silo-pkg/v3` v3.11.0](https://github.com/pgsty/silo-pkg/releases/tag/v3.11.0)，与服务端保持一致，源码 import 路径不变。
- 三个 etcd 相关模块由 3.6.9 一致升级至 **3.7.1**，包含 [GO-2026-6107 / CVE-2026-73500](https://pkg.go.dev/vuln/GO-2026-6107) 的修复。
- `grpc-gateway` 升至 2.29.0、`zap` 升至 1.28.0、`go.yaml.in/yaml/v3` 升至 3.0.5，两个 `genproto/googleapis` 模块对齐到 SILO 已使用的 2026-05-26 修订点。
- `go-systemd` 有意沿用 SILO 的共享可移植性 pin 保持在 22.6.0：22.7.0 的 daemon 包无法在 NetBSD 上编译，而 mcli 本身只链接 journal 包。

## 修复 Metrics JSON Panic {#metrics-fix}

此前执行 `mcli --json admin prometheus metrics` 时，无论使用 v2 还是 v3 Metrics API，都会直接 panic：

```text
panic: Invalid name validation scheme requested: unset
```

该问题存在于已经发布的 20260804 与 20260806 客户端中。`madmin-go/v3` 使用了 Prometheus `TextParser` 的零值，而从 `prometheus/common` 0.66 起，解析器必须显式选择名称校验方案。mcli 现在按上游 madmin 的修复使用 `UTF8Validation` 构造解析器，解析失败时返回正常错误而不是 panic，并按名称确定性输出 Metrics Family。纯文本 Metrics 输出保持不变。

## 第三方许可证与发行制品 {#notices}

- `CREDITS` 由六个发行目标实际链接的运行时模块并集确定生成：Linux、macOS、Windows，各覆盖 amd64 与 arm64。
- replace 模块按真实源码仓库署名；无归档 LICENSE 文件的模块、次级 LICENSE 与 NOTICE 文件均显式处理。
- CI 会重新生成并比对 `CREDITS`，依赖变更不能再静默造成清单漂移。
- GoReleaser 归档、DEB/RPM/APK 软件包、开发镜像、hotfix 镜像及正式多架构容器现在全部携带 `LICENSE`、`NOTICE` 与 `CREDITS`。
