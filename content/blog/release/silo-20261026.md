## Server changes since 20261018 {#server-20261026}

<span id="server-20261025"></span><span id="changes"></span>

- **LDAP and IAM:** restore login for long normalized LDAP DNs without treating unreadable revocation records as absent ([#250](https://github.com/pgsty/silo/pull/250)). Only a valid IAM key with an ASCII path component over 255 bytes receives the missing-record treatment; writing overlong records remains unsupported. Policy reloads no longer hold the authentication-cache lock during storage access, publish a replacement only after a complete load, and retain IAM write ordering. Request cancellation reaches KMS and SSE-S3 decryption without shortening the caller's policy-query deadline.
- **Built-in policies and bucket inventory:** Reset immediately restores the native policy. Delayed peer/etcd notifications reload committed state and preserve subsequent edits; policy-in-use checks and custom-policy deletion remain effective. Account-info reads the live bucket list so successful creation/deletion appears after refresh; object usage remains scanner-derived.
- **Multi-pool deletion:** retain authoritative copies when ordinary or bulk cleanup fails, choose an available pool for new delete markers, and protect tier objects referenced by surviving copies ([#257](https://github.com/pgsty/silo/pull/257), [#256](https://github.com/pgsty/silo/issues/256)). This does not add strict cross-pool read recovery.
- **Lifecycle expiration:** retain remote tier payloads when expiration only adds a delete marker, including non-null versions in versioning-suspended buckets. The prior version remains readable until that version is permanently deleted and no retained reference needs its payload ([#253](https://github.com/pgsty/silo/pull/253), [#252](https://github.com/pgsty/silo/issues/252)).
- **Multipart replication:** forward the `FULL_OBJECT` checksum type for CRC multipart replicas, avoiding `BadDigest` at the target ([#255](https://github.com/pgsty/silo/pull/255), [#254](https://github.com/pgsty/silo/issues/254)).
- **Storage RPC and timeout compatibility:** forward deletion options, including the previous data directory used by overwrite rollback. Retain the established drive/RPC deadlines, cancellation, object locking, read quorum and healing policy. The final release removes the draft's admitted-I/O draining and mutation-guard scheme (including [#258](https://github.com/pgsty/silo/pull/258)); it does not claim ownership-fenced rollback or protection against all late commits. See the [final maintenance change](https://github.com/pgsty/silo/commit/dcc2f20ba) and [failure boundaries](/blog/design/multi-pool-object-consistency/#maintenance-20261026).
- **Dependencies and delivery:** update SFTP, etcd, NATS, cloud SDKs and other Go dependencies; preserve Kafka's default protocol 2.1, CLI formatting and NetBSD selections; fix legacy DARE v1 unsealing while retaining v2 writes. Bundle mcli 20261026 in images, the verified installer and Helm client jobs. Ship Windows ZIP archives, static curl 8.23.0 and the certificate-trust mitigation described below. Correct RPM signer verification during the final SBOM/provenance refresh.
- **Documentation:** incorporate the single-node MinIO migration guide ([#228](https://github.com/pgsty/silo/pull/228)), reconcile operational defaults and move the supported upgrade instructions to the [migration entry point](/compatibility/migration/).

The release retains the Object Lock, IAM authorization, durable STS revocation, migration and listing repairs already delivered in [20261018](/blog/release/silo-20261018/). The dependency security inventory below distinguishes newly adopted fixes from earlier repairs and findings in unused code.

## mcli changes since 20261018 {#mcli}

- **Identity isolation:** separate cached S3 and administration clients by credentials, trust, proxy, resolver and header settings; preserve credential refresh and token-file rotation ([#50](https://github.com/pgsty/mc/issues/50), [#55](https://github.com/pgsty/mc/pull/55)).
- **Resync status:** consume JSON streams through the terminal state, preserve output for completed jobs, report disabled replication, and stop waiting on Failed/Canceled in TTY mode. Calculate throughput without integer overflow after roughly 8.6 GiB ([#48](https://github.com/pgsty/mc/issues/48), [#49](https://github.com/pgsty/mc/issues/49), [#52](https://github.com/pgsty/mc/issues/52)).
- **Honest operation results:** resync start/cancel return nonzero on partial failure while retaining per-bucket errors ([#51](https://github.com/pgsty/mc/issues/51)). Successfully querying a job already in Failed/Canceled still exits zero. `admin info --json` now returns nonzero on request failure while preserving JSON error output.
- **Batch observation:** keep watching when live metrics are missing, emit an additive `pending` JSON state, use bounded persisted-status fallback, and avoid IOPs overflow for large object counts ([#53](https://github.com/pgsty/mc/issues/53), [#54](https://github.com/pgsty/mc/issues/54)).
- **Alias regions:** honor persisted `region` values with precedence `MC_REGION`, `AWS_REGION`, alias configuration, then discovery; isolate signing regions in client caches ([#44](https://github.com/pgsty/mc/pull/44)). No `alias set --region` flag is added.
- **SDK:** reject short sequential/parallel multipart streams, preserve `ReadAt` EOF and negative-offset behavior and post-`Stat` read/seek bounds, deduplicate fallback delete errors, and accept HTTP 200/204 for bucket-replication removal. Genuine errors such as 403 remain errors.
- **Packaging and help:** Go 1.27.3, GoReleaser 2.19.0, Windows ZIP ([#45](https://github.com/pgsty/mc/issues/45)), refreshed help links and clearer messages for disabled server-update/SUBNET commands. Keep existing CLI configuration and `MC_*` variables.

Scripts must handle `pending` and nonzero exits for partially failed mutations. This client update requires no Server protocol change. A download interrupted mid-stream still fails; SIGINT during multipart upload exits 130, and incomplete upload parts may need explicit cleanup. [Complete client history](https://github.com/pgsty/mc/compare/RELEASE.2026-10-18T00-00-00Z...RELEASE.2026-10-26T00-00-00Z).

## Upgrade and failure boundaries {#upgrade}

1. Back up IAM state, configuration and encryption keys. Upgrade Server processes and replication sites as a coordinated stack, following the [IAM guide](/operations/replication/iam-upgrade/). Mixed old/new processes sharing one IAM backend and rolling downgrades remain unsupported.
2. Verify LDAP/OIDC login, built-in policy Reset, bucket refresh, versioned reads, replication and encrypted-object decryption. Upgrade the sender for the `FULL_OBJECT` replication repair, then inspect its pending queue.
3. Use ZIP for new Windows archives; Linux/macOS retain tar.gz. Update scripts for mcli's `pending` state and partial-failure exits. Existing configuration names and storage formats remain supported.
4. Preserve the earlier multipart limitation: public listing remains node-local cache/exact-key lookup; the retired strict switch is ignored. [#79](https://github.com/pgsty/silo/issues/79) and [#217](https://github.com/pgsty/silo/issues/217) are not declared fixed. Webhook hot reload [#249](https://github.com/pgsty/silo/pull/249) is not included, and broader performance symptoms in [#251](https://github.com/pgsty/silo/issues/251) remain open.

**A returned timeout does not prove that underlying I/O stopped or that a write failed to commit.** Late commits, delayed rollback and stale values/tags remain possible after partial failures, lease loss or network partitions. This release adds no distributed fencing and cannot restore already-lost objects, tier payloads or metadata. A later unconditional PUT does not establish ordering against an unresolved request.

## Included runtime security fixes {#runtime-fixes}

<span id="security"></span>

### Go and certificate trust {#go-trust}

**[CVE-2026-111943 / GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809)**: Go 1.27.3 rejects known untrustworthy intermediate certificates in `crypto/x509`, protecting TLS verification even when host trust stores have not yet been updated. All five primary projects and the standalone debugging modules are built with Go 1.27.3.

In addition, the UBI container trust stores for SILO, mcli, and KES apply the root certificate blocklist from [Red Hat RHSB-2026-012](https://access.redhat.com/security/vulnerabilities/RHSB-2026-012). Because blocking a root rejects every certificate chain anchored under that root, this container-level mitigation is broader than Go 1.27.3's intermediate-certificate check; external services still using certificates chained to those roots must rotate their certificate chains. See [Locally mitigated items](#local-mitigations) below for the UBI CA package status.

## Historical repairs, not newly fixed vulnerabilities {#historical-findings}

Module-path binary scanners continue to match SILO against **CVE-2025-27414, CVE-2026-33322, CVE-2026-33419, CVE-2026-34204, CVE-2026-39414, CVE-2026-40344, CVE-2026-41145, and CVE-2026-42600** because SILO retains the `github.com/minio/minio` module path and those upstream advisories specify open-ended version ranges. All eight issues were patched and verified in earlier SILO releases; see [SFTP](https://pkg.go.dev/vuln/GO-2025-3495), [OIDC](/blog/security/cve-2026-33322/), [LDAP](/blog/security/cve-2026-33419/), [replication metadata](/blog/security/cve-2026-34204/), [CSV](/blog/security/cve-2026-39414/), [Snowball](/blog/security/cve-2026-40344/), [signature validation](/blog/security/cve-2026-41145/), and [ReadMultiple](/blog/security/cve-2026-42600/).

## Compatibility and dependency regression evidence {#compatibility}

To prevent reproduced regressions in CLI table formatting, character-width calculation, and NetBSD cross-compilation, this batch pins `tablewriter 0.0.5`, `go-humanize 1.0.1`, `go-runewidth 0.0.29` in the root modules, and `go-systemd/v22 22.6.0` (while `xattr` retains its existing width-library combination). In addition:
- Kafka notification targets explicitly initialize the protocol version default to `2.1` before applying user settings;
- DARE encryption retains 32-byte keys and v2 writes while fixing buffer handling when unsealing legacy v1 payloads;
- `pgzip` retains the integrity check that returns `unexpected EOF` when a gzip checksum trailer is missing.
