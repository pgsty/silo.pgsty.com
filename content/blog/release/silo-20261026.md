## Server changes since 20261018 {#server-20261026}

<span id="server-20261025"></span><span id="changes"></span>

- **LDAP and IAM ([#250](https://github.com/pgsty/silo/pull/250)):** Restores group-based login for LDAP users whose normalized DNs exceed 255 bytes in a single ASCII path component by treating missing optional IAM records on those paths as absent, while continuing to fail closed on unreadable revocation records or storage errors (writing overlong path records remains unsupported on the object backend). Policy reloads no longer hold the authentication-cache lock during storage I/O, swap the cache only after a complete load, and preserve IAM write ordering. Request cancellation now propagates to KMS and SSE-S3 decryption paths without shortening the caller's policy-query deadline.
- **Built-in policy Reset and live bucket inventory:** Resetting an overridden built-in policy immediately restores the native policy definition on the next read, while delayed peer/etcd notifications reload committed state without clobbering newer edits (in-use checks, delete revisions, and custom-policy deletion remain unchanged). Console's `account-info` endpoint now reads the live bucket inventory so newly created or deleted buckets appear immediately on refresh, while object usage totals remain scanner-derived.
- **Multi-pool deletion safety ([#257](https://github.com/pgsty/silo/pull/257), [#256](https://github.com/pgsty/silo/issues/256)):** Ordinary and bulk deletes clean non-authoritative duplicate pools before removing the authoritative copy, select an available pool when writing new delete markers, and protect remote-tier payloads still referenced by surviving copies.
- **Versioned lifecycle expiration ([#253](https://github.com/pgsty/silo/pull/253), [#252](https://github.com/pgsty/silo/issues/252)):** Retains remote tier payloads whenever lifecycle expiration only inserts a delete marker (including non-`null` versions in versioning-suspended buckets), reclaiming remote tier objects only when a historical version is permanently purged and no surviving reference needs its payload.
- **Multipart replication ([#255](https://github.com/pgsty/silo/pull/255), [#254](https://github.com/pgsty/silo/issues/254)):** Forwards the `FULL_OBJECT` checksum type when replicating CRC multipart objects so the target cluster does not reject the replica with `BadDigest`.
- **Storage RPC and timeout semantics:** Forwards storage RPC deletion options (including the previous data directory needed for overwrite rollback) while preserving existing drive/RPC deadlines, request cancellation, object locking, read quorum, and healing rules. The final release withdrew the 20261025 draft's admitted-I/O draining waits and per-object mutation guards (including [#258](https://github.com/pgsty/silo/pull/258)) in [`dcc2f20ba`](https://github.com/pgsty/silo/commit/dcc2f20ba); see the [multi-pool object consistency record](/blog/design/multi-pool-object-consistency/#maintenance-20261026).
- **Dependencies, packaging, and delivery:** Updates SFTP, etcd, NATS, cloud SDKs, and other Go modules; preserves Kafka's default protocol `2.1`, CLI formatting, and NetBSD compatibility; and fixes legacy DARE v1 unsealing while keeping v2 writes. Container images, the verified installer, and Helm client jobs bundle mcli 20261026. Windows archives now ship as `.zip`, static `curl` is updated to `8.23.0` with the certificate-trust mitigation described below, and RPM signer verification is fixed during the final SBOM/provenance refresh.
- **Documentation and migration:** Incorporates the single-node MinIO migration guide ([#228](https://github.com/pgsty/silo/pull/228)), reconciles operational defaults, and consolidates upgrade instructions under the [migration guide](/compatibility/migration/).

This release retains all Object Lock, IAM authorization, durable STS revocation, pool-migration, and `LIST` recovery repairs shipped in [20261018](/blog/release/silo-20261018/). The dependency security inventory below separates newly adopted fixes from earlier repairs and scanner findings in unused code paths.

## mcli changes since 20261018 {#mcli}

- **Client identity cache isolation ([#50](https://github.com/pgsty/mc/issues/50), [#55](https://github.com/pgsty/mc/pull/55)):** Isolates cached S3 and admin clients by credentials, TLS trust, proxy, custom resolver, and request headers while preserving credential refresh and token-file rotation.
- **Replication resync status and throughput ([#48](https://github.com/pgsty/mc/issues/48), [#49](https://github.com/pgsty/mc/issues/49), [#52](https://github.com/pgsty/mc/issues/52)):** `admin replicate resync status --json` drains the status stream through terminal `Completed`, `Failed`, or `Canceled` states so completed jobs emit their final JSON record; explicitly reports when replication is disabled; stops waiting on `Failed` or `Canceled` in TTY mode; and fixes integer overflow in throughput calculations past ~8.6 GiB.
- **Honest exit codes ([#51](https://github.com/pgsty/mc/issues/51)):** `resync start` and `resync cancel` retain per-bucket error details and return a nonzero exit code when any bucket fails, while `resync status` continues to exit `0` when successfully inspecting an already `Failed` or `Canceled` job. `admin info --json` also exits nonzero on request failure while preserving its JSON error output.
- **Batch job observation ([#53](https://github.com/pgsty/mc/issues/53), [#54](https://github.com/pgsty/mc/issues/54)):** `batch status` continues watching when live metrics are not yet available, emits a `pending` status instead of treating queued or missing samples as complete, falls back to bounded persisted-status queries when the metric stream ends early, and fixes IOPs integer overflow on large object counts.
- **Alias regions ([#44](https://github.com/pgsty/mc/pull/44)):** Honors persisted alias `region` settings with precedence `MC_REGION` → `AWS_REGION` → alias configuration → bucket-location discovery, and isolates signing regions across cached clients (without adding an `alias set --region` CLI flag).
- **SDK fixes:** Rejects truncated sequential or parallel multipart streams; preserves `ReadAt` EOF/negative-offset semantics and post-`Stat` read/seek bounds; deduplicates fallback batch-delete errors; and accepts both HTTP `200` and `204` when removing bucket replication configurations (while still reporting `403` and other real errors).
- **Packaging and help ([#45](https://github.com/pgsty/mc/issues/45)):** Builds with Go 1.27.3 and GoReleaser 2.19.0, switches Windows archives to `.zip`, refreshes help URLs and disabled server-update/SUBNET messages, and preserves existing CLI configuration and `MC_*` environment variables.

Automation scripts should handle the `pending` batch state and nonzero exit codes on partially failed resync start/cancel commands. Upgrading `mcli` requires no Server protocol change. Mid-stream download interruptions still fail immediately; `SIGINT` during a multipart upload exits `130`, and incomplete upload parts may require explicit cleanup. See the [complete client commit history](https://github.com/pgsty/mc/compare/RELEASE.2026-10-18T00-00-00Z...RELEASE.2026-10-26T00-00-00Z).

## Upgrade and failure boundaries {#upgrade}

1. **Coordinated upgrade:** Back up IAM state, configuration, and encryption keys, and upgrade all Server nodes and replication peers together following the [IAM upgrade guide](/operations/replication/iam-upgrade/). Running mixed old/new Server versions against a shared IAM backend or performing rolling downgrades remains unsupported.
2. **Post-upgrade checks:** Verify LDAP/OIDC login, built-in policy Reset, bucket list refresh, versioned reads, cross-site replication, and encrypted-object decryption. The `FULL_OBJECT` multipart replication fix requires upgrading the sending Server first and then checking its pending replication queue.
3. **Archive formats and scripts:** Windows archives now use `.zip` (Linux and macOS retain `.tar.gz`); update automation scripts for `mcli batch status` `pending` outputs and nonzero exit codes on partially failed `resync start/cancel` commands. Existing environment variables, configuration filenames, and on-disk formats remain unchanged.
4. **Known multipart and issue scope:** Public `ListMultipartUploads` continues to use the node-local in-memory cache and exact-key lookup, ignoring the retired `strict` switch with a startup warning. Issues [#79](https://github.com/pgsty/silo/issues/79) and [#217](https://github.com/pgsty/silo/issues/217) remain open, webhook hot-reload PR [#249](https://github.com/pgsty/silo/pull/249) is not included, and broader performance symptoms remain tracked in [#251](https://github.com/pgsty/silo/issues/251).

**Storage timeout and consistency boundary:** A client-visible request timeout does not guarantee that underlying disk or RPC I/O has stopped or that the write failed to commit. Late commits, delayed rollbacks, and stale values or tags remain possible after partial drive failures, lock lease expiration, or network partitions. This release does not add distributed lock fencing and cannot automatically recover previously lost objects, remote tier payloads, or metadata.

## Included runtime security fixes {#runtime-fixes}

<span id="security"></span>

### Go and certificate trust {#go-trust}

**[CVE-2026-111943 / GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809)**: Go 1.27.3 rejects known untrustworthy intermediate certificates in `crypto/x509`, protecting TLS verification even when host trust stores have not yet been updated. All five primary projects and the standalone debugging modules are built with Go 1.27.3.

In addition, the UBI container trust stores for SILO, mcli, and KES apply the root certificate blocklist from [Red Hat RHSB-2026-012](https://access.redhat.com/security/vulnerabilities/RHSB-2026-012). Because blocking a root rejects every certificate chain anchored under that root, this container-level mitigation is broader than Go 1.27.3's intermediate-certificate check; external services still using certificates chained to those roots must rotate their certificate chains. See [Locally mitigated items](#local-mitigations) below for the UBI CA package status.

## Compatibility and dependency regression evidence {#compatibility}

To prevent reproduced regressions in CLI table formatting, character-width calculation, and NetBSD cross-compilation, this batch pins `tablewriter 0.0.5`, `go-humanize 1.0.1`, `go-runewidth 0.0.29` in the root modules, and `go-systemd/v22 22.6.0` (while `xattr` retains its existing width-library combination). In addition:
- Kafka notification targets explicitly initialize the protocol version default to `2.1` before applying user settings;
- DARE encryption retains 32-byte keys and v2 writes while fixing buffer handling when unsealing legacy v1 payloads;
- `pgzip` retains the integrity check that returns `unexpected EOF` when a gzip checksum trailer is missing.

The October 22–23 candidate validation (built with Go 1.27.3 on both the rollback baseline and the candidate, with persisted-data acceptance run on a single-node four-drive Linux arm64 setup) passed:

- Service restart, missing-shard healing recovery, and CLI output checks;
