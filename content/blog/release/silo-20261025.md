**Status on 2026-10-25: silo-pkg v3.15.1 is released; mcli 20261025 is prepared but not published; the maintenance batch remains incomplete.** **20261025** is a coordinated maintenance batch shared across **SILO, mcli, SILO Console, silo-pkg, and KES**, delivering the Go 1.27.3 toolchain upgrade, dependency updates, and associated security fixes. The remaining component version numbers, Git tags, commit hashes, and artifact digests will be added as each component ships; the [downloads page](/download/) continues to serve the current production releases.

First component delivered: [silo-pkg v3.15.0](https://github.com/pgsty/silo-pkg/releases/tag/v3.15.0), from commit [`717969b63fa7`](https://github.com/pgsty/silo-pkg/commit/717969b63fa77679a10b376c5396657cf009ec5e). This shared Go library raises the minimum Go version from 1.26 to **1.27.3**, updates 13 dependency modules compared with v3.14.3, and retains its policy optimizations and authorization semantics. Final-commit [Go](https://github.com/pgsty/silo-pkg/actions/runs/40059985563), [LDAP](https://github.com/pgsty/silo-pkg/actions/runs/40059985572), and [VulnCheck](https://github.com/pgsty/silo-pkg/actions/runs/40059985555) CI passed; downstream consumers take the update by adopting the released module and rebuilding.

On October 25, [silo-pkg v3.15.1](https://github.com/pgsty/silo-pkg/releases/tag/v3.15.1) followed from commit [`8893479a348a`](https://github.com/pgsty/silo-pkg/commit/8893479a348a46ca82bc7a6dc86bd86a1dc71973). It updates minio-go from v7.4.1 to upstream commit `ab93db7ba435` (`v7.4.2-0.20261020194015-ab93db7ba435`), covering six fixes: short sequential and parallel multipart streams, `ReadAt` EOF and negative offsets, read/seek bounds after `Stat`, and duplicate batch-delete error results. Upstream has not tagged v7.4.2. Go remains 1.27.3; formatting and NetBSD compatibility selections remain in place. This patch adds no new CVE fix. Other components receive these SDK fixes only after adopting the module and rebuilding.

The inventory below reflects dependency, build, and advisory audits conducted on 2026-10-22 and 2026-10-23, plus the incremental Go dependency updates on October 24. System-package and frontend security entries retain the review dates stated below. CVEs that appear across multiple components are recorded once under their primary dependency.

## Included runtime security fixes {#runtime-fixes}

### Go and certificate trust {#go-trust}

**[CVE-2026-111943 / GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809)**: Go 1.27.3 rejects known untrustworthy intermediate certificates in `crypto/x509`, protecting TLS verification even when host trust stores have not yet been updated. All five primary projects and the standalone debugging modules are built with Go 1.27.3.

In addition, the UBI container trust stores for SILO, mcli, and KES apply the root certificate blocklist from [Red Hat RHSB-2026-012](https://access.redhat.com/security/vulnerabilities/RHSB-2026-012). Because blocking a root rejects every certificate chain anchored under that root, this container-level mitigation is broader than Go 1.27.3's intermediate-certificate check; external services still using certificates chained to those roots must rotate their certificate chains. See [Locally mitigated items](#local-mitigations) below for the UBI CA package status.

## Compatibility and pre-release validation {#compatibility}

To prevent reproduced regressions in CLI table formatting, character-width calculation, and NetBSD cross-compilation, this batch pins `tablewriter 0.0.5`, `go-humanize 1.0.1`, `go-runewidth 0.0.29` in the root modules, and `go-systemd/v22 22.6.0` (while `xattr` retains its existing width-library combination). In addition:
- Kafka notification targets explicitly initialize the protocol version default to `2.1` before applying user settings;
- DARE encryption retains 32-byte keys and v2 writes while fixing buffer handling when unsealing legacy v1 payloads;
- `pgzip` retains the integrity check that returns `unexpected EOF` when a gzip checksum trailer is missing.

The October 22–23 candidate validation (built with Go 1.27.3 on both the rollback baseline and the candidate, with persisted-data acceptance run on a single-node four-drive Linux arm64 setup) passed:
- Full compilation and applicable `-race` and lint suites;
- Encrypted-object read and rollback verification across the old and new dependency stacks;
- Service restart, missing-shard healing recovery, and CLI output checks;
- End-to-end Console object uploads/downloads, ZIP archive previews, WebSocket sessions, and metrics charts.

The candidate sources with the October 24 dependency updates passed these additional checks:

- Full race suites for silo-pkg, mcli, and KES; API / pkg / cmd race suites for Console; the full SILO test suite and focused SFTP, IAM, and Parquet race tests. Lint, module verification, and dependency tidiness checks passed for all five projects.
- SFTP object reads, writes, listing, deletion, Unicode names, transfer block boundaries, and read-only data protection through the SILO driver against HTTP / HTTPS S3 backends. Upstream read-only server and symlink deletion regression tests passed. Both dependency baselines passed the new object-operation tests.
- JWX signature and time-claim boundary comparisons; 68 CLI output comparisons with no new differences, normalizing only existing metadata map ordering.
- Local etcd mTLS, account authentication, transactions, watches, leases, and old → new → old clients reading across server restarts; NATS / STAN message persistence, ACKs, durable subscription cursors, and reconnection.
- Local Azure / GCS protocol fixtures, KES GCP Secret Manager operations and pagination, the Azure SDK's Arrow decoder tests, and the full upstream procfs parser fixtures. The procfs update corrects bcache units and NVMe sizes, so the corresponding metric values may change to reflect those corrections.
- Native Darwin arm64 and cross-compiled Linux amd64 builds of mcli, Console, SILO, and KES; NetBSD amd64 cross-builds of mcli and SILO.

Linux amd64 package-level Go vulnerability scans of all five projects found no affected imported packages (only the module-level `GO-2026-5932` entry remains, with no imports of the affected OpenPGP subpackages).
