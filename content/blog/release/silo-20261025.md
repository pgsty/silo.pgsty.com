**Status on 2026-10-26: silo-pkg v3.15.1, mcli 20261025, Console v2.5.0 and KES 20261025000000 are released; Server 20261025 remains a Draft Release.** **20261025** is a coordinated maintenance batch across **SILO, mcli, SILO Console, silo-pkg, and KES**, delivering the Go 1.27.3 toolchain upgrade, dependency updates, and associated security and correctness fixes. Remaining component tags and artifact digests will be added as each component ships; the [downloads page](/download/) continues to serve the current production releases.

- **[silo-pkg v3.15.0](https://github.com/pgsty/silo-pkg/releases/tag/v3.15.0)** (commit [`717969b63fa7`](https://github.com/pgsty/silo-pkg/commit/717969b63fa77679a10b376c5396657cf009ec5e)): raises the minimum Go version from 1.26 to **1.27.3**, updates 13 dependency modules over v3.14.3 while preserving policy optimizations and authorization semantics, and passes [Go](https://github.com/pgsty/silo-pkg/actions/runs/40059985563), [LDAP](https://github.com/pgsty/silo-pkg/actions/runs/40059985572), and [VulnCheck](https://github.com/pgsty/silo-pkg/actions/runs/40059985555) CI.
- **[silo-pkg v3.15.1](https://github.com/pgsty/silo-pkg/releases/tag/v3.15.1)** (released October 25 from commit [`8893479a348a`](https://github.com/pgsty/silo-pkg/commit/8893479a348a46ca82bc7a6dc86bd86a1dc71973)): updates upstream `minio-go` from v7.4.1 to pinned commit `ab93db7ba435` (`v7.4.2-0.20261020194015-ab93db7ba435`), bringing six SDK fixes—short sequential and parallel multipart stream detection, `ReadAt` EOF and negative offsets, read/seek bounds after `Stat`, and duplicate batch-delete fallback errors—while retaining Go 1.27.3, output formatting, and NetBSD compatibility pins.

The security and dependency inventory below reflects audits conducted on 2026-10-22 and 2026-10-23, plus the incremental updates from October 24–25. CVEs that appear across multiple components are recorded once under their primary dependency.

### Server 20261025 Draft Release {#server-20261025}

Server tag `RELEASE.2026-10-25T00-00-00Z` is currently a **Draft Release** (package version `20261025000000.0.0`), integrating the released **silo-pkg v3.15.1**, **mcli 20261025** (`dcc78d506f94`), and **Console v2.5.0** (`989fa7150792`) sources along with upstream `minio-go` commit `ab93db7ba435`. Public Server downloads and Docker `latest` tags continue to point to 20261018.

A final review of Server's **280 explicit Go requirements** confirmed that no additional compatible updates are needed (formatting, terminal-width, NetBSD, and no-op instrumentation pins remain in place; subsequent `main` commits in `mc` and `silo-console` touch only release documentation, so Server builds from their tagged commits). Go vulnerability scans report no affected imported packages (`GO-2026-5932` remains a module-level OpenPGP advisory for a subpackage Server does not import).

This draft includes the following storage, replication, lifecycle, and IAM fixes:

- **Write, rollback, and cleanup safety**: wait for admitted storage mutations to finish before releasing local guards or cleaning staging; verify rollback ownership in `UndoWrite` and restore only the overwritten version while preserving later concurrent writes and metadata updates; keep `xl.meta.bkp` backups required by in-flight commits/rollbacks during abandoned-upload cleanup; generate `PUT` timestamps inside the commit lock; and retain existing read-quorum and healing semantics (including readability after a failed partial overwrite).
- **Multi-pool deletion, lifecycle, and multipart replication**: retain authoritative copies during multi-pool deletion when cleanup fails and protect referenced remote tier objects; retain remote tier data when lifecycle expiration on a versioned bucket (including non-null versions in suspended buckets) only writes a delete marker; forward the `FULL_OBJECT` checksum type during multipart replication (thanks to [@botdeniska](https://github.com/botdeniska) for the lifecycle, replication, and multi-pool deletion fixes).
- **IAM and management endpoints**: decouple IAM policy reloads from the authentication-cache lock and propagate KMS cancellation; fix immediate policy reads after built-in policy Reset and live bucket-inventory reads on the account-info endpoint; switch Windows archives to ZIP.

**Pre-release validation:** source [`263ee0510da5`](https://github.com/pgsty/silo/commit/263ee0510da51c555b7257bbe504b22355cac4b0) passed [Go CI](https://github.com/pgsty/silo/actions/runs/40210160701), [VulnCheck](https://github.com/pgsty/silo/actions/runs/40210160735), and [Test Release Pipeline](https://github.com/pgsty/silo/actions/runs/40210160509) before tagging. The local Go suite passed 8,658 tests and subtests (72 skipped) plus 204 targeted `-race` checks, and Windows archives were cross-compiled and structurally verified. Live two-node Server tests (covering both object-backed IAM and etcd) with released Console v2.5.0 and mcli 20261025 verified complete health-report downloads, built-in policy overrides, in-use rejection, immediate Reset reads on both nodes, delayed notifications, custom-policy deletion, persistence across restart, and versioned S3 uploads, tagging, download integrity, and deletion.

**Current storage boundaries:** lease expiration or network partitions can still allow late commits, and partial metadata updates can still expose stale values or tags; split object generations and unavailable pools retain existing read behavior. This release does not add distributed fencing or repair pre-existing inconsistent objects (stricter read refusal and cross-pool recovery diagnostics remain gated behind the `consistency_strict` build tag). Waiting for admitted I/O can lengthen same-object writes or cleanup on a stalled drive, and interrupted cleanup can leave rollback backup files behind; upgrade all writer nodes before relying on the new rollback ownership checks.

### Console v2.5.0 release {#console-250}

[Console v2.5.0](https://github.com/pgsty/silo-console/releases/tag/v2.5.0) is released from commit [`989fa7150792`](https://github.com/pgsty/silo-console/commit/989fa7150792ffe62fe8d045353ed69bd2ec9ad8), built with Go 1.27.3, **silo-pkg v3.15.1**, **mcli 20261025** (`v0.0.0-20261025104502-dcc78d506f94`, matching `RELEASE.2026-10-25T00-00-00Z`), and upstream `minio-go` commit `ab93db7ba435`. A review of Console's 185 explicit Go requirements confirmed that no further updates are needed, keeping the `tablewriter 0.0.5`, `go-humanize 1.0.1`, `go-runewidth 0.0.29`, and `go-systemd 22.6.0` compatibility pins.

Key changes since v2.4.2 (see the [Console CHANGELOG](https://github.com/pgsty/silo-console/blob/v2.5.0/CHANGELOG.md) for the full list):

- **UI and workspace updates**: permission-aware navigation, Overview dashboard, sortable/filterable bucket tables, text/Markdown/CSV previews, Tasks center (canceling a task does not undo completed mutations), identity and policy management updates, and a responsive light/dark interface.
- **Permissions, search, and error reporting**: restore object-workspace entry for write-only users so they can upload objects while listing and reading still enforce their own permissions; honor wildcard bucket-root grants for workspace entry and list controls while preserving prefix restrictions on object operations; surface server JSON error details when object-tag writes are rejected; and discard delayed bucket-search timer updates after navigation so opening an object workspace while code is loading cannot bounce the user back to the bucket list.
- **Built-in policy Reset and live bucket inventory (requires Server 20261025)**: on published Server 20261018, resetting an overridden built-in policy can return HTTP 500 on the first subsequent read, and the account-info endpoint can return a stale cached bucket list after creating or deleting a bucket. Server 20261025 refreshes the policy cache immediately and reads the live bucket list on each account-info request; upgrading standalone Console alone does not replace the Console v2.4.2 embedded in Server 20261018 or update the old Server's cache.
- **High-latency diagnostic streams and health reports ([#63](https://github.com/pgsty/silo-console/issues/63))**: fix truncated reports and WebSocket `1006` closures on high-latency links across all six diagnostics (Health, Trace, Logs, Watch, Speedtest, and Profile)—the sole reader goroutine now waits for the peer `Close` frame under a shared 5-second close budget that does not cap active diagnostic streams (thanks to **Azat / @azataiot** for the reproduction and analysis). Also fix a `madmin v3` version-decoder buffering issue that could consume the start of the next health-report frame and trigger WebSocket `1011` (the upstream [madmin-go fix](https://github.com/minio/madmin-go/commit/a6ab0bcca33f72cfe8448eaff9836fb1d54acc32) landed only in v4; Console retains the v3 API, reuses a single decoder across the stream, and rejects truncated, canceled, or failed responses).

## Included runtime security fixes {#runtime-fixes}

### Go and certificate trust {#go-trust}

**[CVE-2026-111943 / GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809)**: Go 1.27.3 rejects known untrustworthy intermediate certificates in `crypto/x509`, protecting TLS verification even when host trust stores have not yet been updated. All five primary projects and the standalone debugging modules are built with Go 1.27.3.

In addition, the UBI container trust stores for SILO, mcli, and KES apply the root certificate blocklist from [Red Hat RHSB-2026-012](https://access.redhat.com/security/vulnerabilities/RHSB-2026-012). Because blocking a root rejects every certificate chain anchored under that root, this container-level mitigation is broader than Go 1.27.3's intermediate-certificate check; external services still using certificates chained to those roots must rotate their certificate chains. See [Locally mitigated items](#local-mitigations) below for the UBI CA package status.

## Compatibility and pre-release validation {#compatibility}

To prevent reproduced regressions in CLI table formatting, character-width calculation, and NetBSD cross-compilation, this batch pins `tablewriter 0.0.5`, `go-humanize 1.0.1`, `go-runewidth 0.0.29` in the root modules, and `go-systemd/v22 22.6.0` (while `xattr` retains its existing width-library combination). In addition:
- Kafka notification targets explicitly initialize the protocol version default to `2.1` before applying user settings;
- DARE encryption retains 32-byte keys and v2 writes while fixing buffer handling when unsealing legacy v1 payloads;
- `pgzip` retains the integrity check that returns `unexpected EOF` when a gzip checksum trailer is missing.

The October 22–23 candidate validation (built with Go 1.27.3 on both the rollback baseline and the candidate, with persisted-data acceptance run on a single-node four-drive Linux arm64 setup) passed:
- Full compilation and applicable `-race` and lint suites;
- Encrypted-object read and rollback verification across the old and new dependency stacks;
- Service restart, missing-shard healing recovery, and CLI output checks;
- End-to-end Console object uploads/downloads, ZIP archive previews, WebSocket sessions, and metrics charts.

The candidate sources with the October 24 dependency updates passed these additional checks:

- Full race suites for silo-pkg, mcli, and KES; API / pkg / cmd race suites for Console; the full SILO test suite and focused SFTP, IAM, and Parquet race tests. Lint, module verification, and dependency tidiness checks passed for all five projects.
- SFTP object reads, writes, listing, deletion, Unicode names, transfer block boundaries, and read-only data protection through the SILO driver against HTTP / HTTPS S3 backends. Upstream read-only server and symlink deletion regression tests passed. Both dependency baselines passed the new object-operation tests.
- JWX signature and time-claim boundary comparisons; 68 CLI output comparisons with no new differences, normalizing only existing metadata map ordering.
- Local etcd mTLS, account authentication, transactions, watches, leases, and old → new → old clients reading across server restarts; NATS / STAN message persistence, ACKs, durable subscription cursors, and reconnection.
- Local Azure / GCS protocol fixtures, KES GCP Secret Manager operations and pagination, the Azure SDK's Arrow decoder tests, and the full upstream procfs parser fixtures. The procfs update corrects bcache units and NVMe sizes, so the corresponding metric values may change to reflect those corrections.
- Native Darwin arm64 and cross-compiled Linux amd64 builds of mcli, Console, SILO, and KES; NetBSD amd64 cross-builds of mcli and SILO.

Linux amd64 package-level Go vulnerability scans of all five projects found no affected imported packages (only the module-level `GO-2026-5932` entry remains, with no imports of the affected OpenPGP subpackages).
