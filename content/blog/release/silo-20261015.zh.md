## 对象锁修复 {#object-lock}

- **SN-2026-015 — 保留期修改授权（[#234](https://github.com/pgsty/silo/pull/234)）**：每次 `PutObjectRetention` 请求在读取对象状态前，必须携带请求体中的 Object Lock 条件键通过 `s3:PutObjectRetention` 鉴权。缩短、清除未到期 `GOVERNANCE` 保留期或改变其模式时，必须同时具备显式 bypass 请求头与 `s3:BypassGovernanceRetention` 权限（不能绕过基础 `s3:PutObjectRetention` 的 `Deny`）。清除保留期按剩余 `0` 天求值，远期日期计算不再溢出饱和。
- **SN-2026-016 — 保护已有版本免受原位覆写（[#235](https://github.com/pgsty/silo/pull/235)）**：客户端指定写入 `versionId` 必须具备可信复制权限（`s3:ReplicateObject`）。目录 `null` 版本与持久化分片上传目标在实际覆写前、持有目标写锁时复查锁状态（覆盖升级前创建或从旧暂存状态恢复的分片上传），确保既有 `GOVERNANCE`、`COMPLIANCE` 与 Legal Hold 保护生效；锁状态读取失败时拒绝写入。
- **发行前置门禁（[#237](https://github.com/pgsty/silo/pull/237)）**：发行构建流水线新增 Object Lock 竞态回归前置检查，覆盖慢请求体目录覆写、预检读取失败、旧分片完成覆写 `COMPLIANCE` 以及恢复上传 UUID 碰撞。

详见[安全公告](/zh/blog/security/20260926-governance-retention-bypass/)与[修复设计](/zh/blog/design/governance-retention-bypass-repair/)。

## 升级要求 {#upgrade}

1. **全节点与复制站点升级**：升级全部 Server 进程及所有接受 S3 写入的复制站点，避免未修复节点继续放行未授权的保留期修改或原位覆写。
2. **核对策略权限**：仅授予 `s3:BypassGovernanceRetention` 而未授予 `s3:PutObjectRetention`、或依赖 bypass 绕过保留期条件键的请求将返回 `403 AccessDenied`。
3. **指定 `versionId` 写入限制**：普通 S3 客户端写入（含 root 签名请求）不得指定目标 `versionId`；可信复制保留版本 ID，`mcli batch replicate` 写入 SILO 时目标凭据需具备 `s3:ReplicateObject`。
4. **锁状态不可读时拒绝覆写**：已锁定的目录对象与已有分片目标不可被覆写；若底层锁元数据读取失败，需先恢复存储盘健康再重试。
5. **历史数据排查**：升级前已发生的异常保留期变更或覆写不会自动回滚，请结合审计日志核查（从 20260916 之前版本升级时请一并参考[九月版升级要求](/zh/blog/release/silo-20260916/#upgrade)）。
