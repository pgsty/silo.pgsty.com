**发行版：**[RELEASE.2026-10-18T00-00-00Z](https://github.com/pgsty/kes/releases/tag/RELEASE.2026-10-18T00-00-00Z) · **软件包：**`20261018000000.0.0` · **源码：**[`2f7e741db905`](https://github.com/pgsty/kes/commit/2f7e741db905d7ea755967b29666657d819d7ad0)。

这是 PGSTY 维护的密钥加密服务首个发行版。**KES 是独立服务**，供需要外部密钥服务的 SILO 部署使用；它不嵌入 Server，未加密部署也不必安装。KES 已独立发布，Server 20261018 已正式发布，参见[组件矩阵](/zh/compatibility/versions/)。

## 变更 {#changes}

- 建立 PGSTY 维护与分发渠道，保留上游版权、署名及第三方许可证。可执行程序和软件包仍名为 `kes`，模块仍为 `github.com/minio/kes`。
- 使用 **Go 1.27.2** 构建，更新依赖，将 AWS Secrets Manager 从 AWS SDK for Go v1 迁移至 **v2**。保留 YAML 字段、显式凭据优先级、配置端点与密钥存储格式；继续忽略 `~/.aws/config` 和 SDK 端点环境变量覆盖。
- 保留 KES HTTP API、`MINIO_KMS_KES_*` 配置、既有根密钥及加密对象。现有 SILO/KES 集成无需修改 Server 代码或迁移密钥。
- 增加 SILO 搭配 OpenBao KV v2、Moto Secrets Manager 模拟器的升级、回滚与重启测试。每次版本切换都重启 SILO，避免密钥缓存掩盖兼容问题。
- 提供签名标签、构建证明、签名 RPM 与非 root 容器镜像。禁用 `kes update`，通过固定版本的 PGSTY 制品、软件包或镜像升级。

## 部署与升级 {#upgrade}

SILO 加密对象内容，KES 验证密钥请求并封装或解封装数据密钥，OpenBao 持久化 KES 根密钥。`MINIO_KMS_KES_ENDPOINT` 应指向 **KES**，不是 OpenBao。[设计说明](/zh/blog/design/kes-openbao/)介绍职责、故障行为与恢复要求。

启动 KES 前配置 TLS、应用身份、访问策略与持久密钥存储。容器以 UID/GID `1000:1000` 运行，配置和证书必须对该用户可读。Linux 软件包安装 `/usr/local/bin/kes`，不会启动未配置的服务。开发模式只把密钥保存在内存中。

升级前备份原密钥存储和配置。验证旧对象解密、新加密对象写入，以及重启 KES 和 SILO 后的读取。回滚时保留同一套根密钥；仅恢复对象数据、不恢复其必需密钥，无法完成恢复。

## 交付与验证 {#delivery}

**19 个发布附件**包含六个 Linux/macOS/Windows amd64/arm64 压缩包、六个 Linux RPM/DEB/APK 软件包、一份压缩包校验清单与六份软件包校验文件。发布记录确认已核验全部下载摘要、六个平台二进制的源码与平台标记、六个软件包载荷、两份 RPM 签名及 11 份 GitHub 构建证明。参见[发布工作流](https://github.com/pgsty/kes/actions/runs/39050774745)。

官方容器为 `docker.io/pgsty/kes:RELEASE.2026-10-18T00-00-00Z`，支持 Linux amd64/arm64。已发布的镜像索引摘要为：

```text
sha256:c2d1a63d15052dfd2854bec9db3fc6846dd74fd6fdf43079f338f36e7a3d5f04
```

[Docker 发布记录](https://github.com/pgsty/kes/actions/runs/39051676783)覆盖两种架构。发布记录还确认了匿名访问，以及 ARM64 下的 TLS 认证、OpenBao AppRole 访问、数据密钥加解密、重启持久性和未认证请求拒绝。

维护验收路径为 **SILO + PGSTY KES + OpenBao KV v2**。KES 发布矩阵测试了 SILO 20260903、20260916，上游 KES `2025-03-12T09-35-18Z`，以及使用 SDK v1 的 PGSTY 基线。Moto 提供本地协议与存储覆盖；**尚未在真实 AWS 账户中验收 IAM 和服务行为**。这些测试不代表所有继承的密钥后端或最终 Server 20261018 制品都通过验收。对原厂 MinIO 的兼容尽最大努力。
