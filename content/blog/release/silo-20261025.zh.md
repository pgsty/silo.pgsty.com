**2026-10-25 状态：silo-pkg v3.15.1、mcli 20261025 与 Console v2.5.0 已发布；统一维护批次仍未完成。** **20261025** 是由 **SILO、mcli、SILO Console、silo-pkg 与 KES** 共用的统一维护批次，集中交付 Go 1.27.3 工具链升级、依赖更新及相关安全修复。其余组件的具体版本号、Git 标签、提交哈希与制品摘要将在各自发布时填入；当前[下载入口](/zh/download/)继续指向既有正式版本。

首个组件交付：[silo-pkg v3.15.0](https://github.com/pgsty/silo-pkg/releases/tag/v3.15.0)，源码提交 [`717969b63fa7`](https://github.com/pgsty/silo-pkg/commit/717969b63fa77679a10b376c5396657cf009ec5e)。该 Go 基础库将最低 Go 版本从 1.26 升至 **1.27.3**，相对 v3.14.3 更新 13 个依赖模块，并保留其策略优化与授权语义。正式提交的 [Go](https://github.com/pgsty/silo-pkg/actions/runs/40059985563)、[LDAP](https://github.com/pgsty/silo-pkg/actions/runs/40059985572) 和 [VulnCheck](https://github.com/pgsty/silo-pkg/actions/runs/40059985555) CI 均通过；下游项目升级该模块版本后重新编译即可生效。

10 月 25 日追加发布 [silo-pkg v3.15.1](https://github.com/pgsty/silo-pkg/releases/tag/v3.15.1)，源码提交 [`8893479a348a`](https://github.com/pgsty/silo-pkg/commit/8893479a348a46ca82bc7a6dc86bd86a1dc71973)。minio-go 从 v7.4.1 更新至上游提交 `ab93db7ba435`（`v7.4.2-0.20261020194015-ab93db7ba435`），纳入 6 项修复：串行与并行分片短流、`ReadAt` 的 EOF 与负偏移、`Stat` 后的读取/定位边界，以及批量删除重复报错。上游尚未发布 v7.4.2 标签。Go 仍为 1.27.3，保留输出格式与 NetBSD 兼容性例外，本补丁未新增 CVE 修复。其他组件须采用该模块并重新构建后才获得这些 SDK 修复。

下文清单基于 2026-10-22 至 2026-10-23 对候选源码与构建环境的依赖、构建及安全公告核对，并纳入 10 月 24 日的 Go 依赖增量升级。系统包与前端安全条目的核对日期仍分别以下文标注为准；同一 CVE 跨多个组件出现时按同一漏洞归并记录。

### Console v2.5.0 正式发布 {#console-250}

[Console v2.5.0](https://github.com/pgsty/silo-console/releases/tag/v2.5.0) 已正式发布，源码为 [`989fa7150792`](https://github.com/pgsty/silo-console/commit/989fa7150792ffe62fe8d045353ed69bd2ec9ad8)。本版采用已发布的 **silo-pkg v3.15.1** 和 **mcli 20261025**；MC replacement 为 `v0.0.0-20261025104502-dcc78d506f94`，对应正式标签 `RELEASE.2026-10-25T00-00-00Z`。minio-go 采用上述上游 `ab93db7ba435` 提交，Go 保持 1.27.3。

相对 v2.4.2，本版交付权限感知导航、Overview、可排序和过滤的存储桶表格、文本／Markdown／CSV 预览、任务中心、身份与策略管理更新，以及响应式明暗界面。策略 Reset 需要配套 Server 的 IAM 缓存修复；任务取消不会撤销已经完成的变更。完整变更见 [Console CHANGELOG](https://github.com/pgsty/silo-console/blob/v2.5.0/CHANGELOG.md)。

**Reset 必须配套更新 Server：** 已发布的 Server 20261018 在重置被覆盖的内置策略后，首次读取策略可能返回 HTTP 500。Server 源码修复已与 Console 2.5.0 通过立即读回默认策略的回归，但该修复尚未进入上述 Server 正式版本。此功能须与 Server 修复一起交付；单独更新 Console 无法修复旧 Server 的策略缓存。

[#63](https://github.com/pgsty/silo-console/issues/63) 报告高延迟网络下健康报告被截断、浏览器收到 WebSocket 1006。本版修复 Health、Trace、Logs、Watch、Speedtest、Profile 共六类诊断：通过现有唯一读取协程等待客户端 Close，发送 Close 与等待响应共用最多五秒预算，活动中的诊断流不受该预算限制。感谢 **Azat（@azataiot）** 提供复现信息和原因分析；该 issue 已在源码修复和回归验证后关闭，修复已包含在 v2.5.0。

真实服务端联调还复现了另一个健康报告问题：madmin v3 的版本解码器可能读入并丢弃下一帧报告的开头，导致 WebSocket 1011。上游[修复](https://github.com/minio/madmin-go/commit/a6ab0bcca33f72cfe8448eaff9836fb1d54acc32) 已进入 v4，但尚未回补 v3 分支。Console 保留 v3 API，使用其签名请求方法，以同一个解码器读取完整数据流；正确关闭响应体，并拒绝截断、取消和报错响应，避免将部分报告当成成功结果。

10 月 25 日在当前主版本范围内复查 Console 的 185 项显式 Go 依赖声明：除采用上述维护组件与 SDK 外，没有需要追加升级的兼容正式版本。保留 tablewriter 0.0.5、humanize 1.0.1、runewidth 0.0.29 和 go-systemd 22.6.0 兼容性例外。madmin v4 的 API 迁移需另行评估，上述健康报告修复不依赖该迁移。mcli 标签之后的 main 仅更新发行文档，Console 使用正式标签对应源码。这些健康报告变更属于正确性修复，不新增 CVE 修复项；下文安全清单继续按各自核对日期解释。

Server 联调候选已采用 pkg v3.15.1、mcli 20261025 正式源码及 Console 2.5.0 候选。两个真实 Server 进程分别使用对象存储 IAM 和 etcd 后端，已验证内置策略覆盖、使用中禁止重置、双节点重置后立即读取、延迟通知、自定义策略删除及重启后的持久化；两个节点内嵌 Console 的 Reset 操作和完整健康报告下载也通过。此项修复不改变对象读取仲裁与 healing 语义。

端到端测试还发现，成功创建或删除存储桶后，Server 的账户信息接口可能返回旧的存储桶列表缓存。候选修复让这个管理接口读取当前列表，代价是每次账户信息请求都执行实时列表读取；API 字段和权限过滤保持原样。固定旧缓存的创建/删除回归及重复浏览器创建/删除流程均已通过。Console 同时恢复了仅有写入权限的用户进入对象工作区的入口：允许上传，对象列举和读取仍分别校验权限。通配符策略对桶根路径的授权也恢复用于入口和列举控件判断，具体对象操作仍受原有前缀范围限制。对象标签写入被拒绝时，现在会显示服务端的 JSON 错误；此前成功响应为空的 API 方法会丢失这些错误详情。成功下载与空响应的处理保持原样。诊断数据流、IAM Reset、列表新鲜度、工作区入口和错误显示修复不新增 CVE 修复项。

桶搜索还会在页面导航后丢弃延迟的查询更新。此前，打开对象工作区时，如果页面代码尚在加载，旧搜索定时器可能把用户带回桶列表。回归测试通过延迟页面代码加载并明确推进搜索定时器覆盖这个竞态。

独立 Console v2.5.0 不会替换 Server 内嵌控制台。配套 Server 修复已进入 main，但尚未发布；本次 Console 发布不附带新 Server 版本。CI 使用配套 Server 源码和本地测试镜像，这些镜像不是分发制品。

## 已纳入的运行时安全修复 {#runtime-fixes}

### Go 与证书信任 {#go-trust}

**[CVE-2026-111943 / GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809)**：Go 1.27.3 在 `crypto/x509` 证书链校验中直接拒绝已知失信的中间证书，在操作系统信任库尚未更新时也能提供兜底拦截。五个主项目及全部独立调试工具均统一使用 Go 1.27.3 编译。

此外，SILO、mcli 与 KES 的 UBI 容器信任库已应用 [Red Hat RHSB-2026-012](https://access.redhat.com/security/vulnerabilities/RHSB-2026-012) 的根证书封禁列表。由于根级封禁会一并拒绝挂靠在这些根证书之下的所有证书链，其拦截范围比 Go 1.27.3 的中间证书黑名单更广；若外部服务仍使用受影响根证书签发的证书链，需先行更换证书。发行版 CA 软件包的跟进状态见下文[本地缓解](#local-mitigations)。

### SFTP 依赖安全加固 {#sftp}

`pkg/sftp 1.13.12` 修复了 10 月 23 日公布的三项安全问题。截至本次核对，它们均**没有 CVE 编号**，以下按 GHSA 单独记录，不计作新增 CVE：

| 公告 | 上游问题 | SILO 适用性 |
| --- | --- | --- |
| [GHSA-xgcg-wgmj-5rw3](https://github.com/pkg/sftp/security/advisories/GHSA-xgcg-wgmj-5rw3)，Medium | `Client.RemoveAll` 跟随顶层符号链接，可能删除目标目录内容 | SILO 服务端未调用该客户端 API |
| [GHSA-47hq-m6q9-3rm6](https://github.com/pkg/sftp/security/advisories/GHSA-47hq-m6q9-3rm6)，Medium | `sftp.Server` 的 ReadOnly 模式允许创建硬链接 | SILO 使用 `NewRequestServer` 与自有 driver，未使用该只读 Server API |
| [GHSA-h959-g3h6-w76c](https://github.com/pkg/sftp/security/advisories/GHSA-h959-g3h6-w76c)，High | ReadOnly 模式允许截断或新建文件 | 同上 |

上游后两条公告的受影响版本区间（affected range）与修复版本字段存在矛盾，本次直接升级至包含实际代码修复的 **1.13.12** 并通过回归测试验证（当前 Go 漏洞库快照停留在 10 月 21 日，尚未收录这三条 10 月 23 日发布的公告）。

### UBI 9.8 尚无适用发行版补丁的扫描记录 {#ubi-residuals}

### 构建阶段与无 CVE 公告 {#other-residuals}

- **Alpine 构建阶段宿主包的 `curl` / `libcurl` 仍为 `8.22.0-r0`**：截至 2026-10-23，Alpine 双架构包索引尚未推送 `8.23.0`。该包仅在容器构建阶段用于下载固定 SHA-256 校验和的源码包，最终打入运行镜像的是从源码编译的静态 `curl 8.23.0`。
- **[GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932)**：`golang.org/x/crypto/openpgp` 已废弃且无上游修复版本（无 CVE 编号）。虽然 `golang.org/x/crypto` 仍在模块图中，但已核查的构建目标均未导入受影响的 `openpgp` 子包。

## 已有历史修复，不属于本次新增漏洞 {#historical-findings}

按模块路径匹配的二进制扫描器仍会对 SILO 报告 **CVE-2025-27414、CVE-2026-33322、CVE-2026-33419、CVE-2026-34204、CVE-2026-39414、CVE-2026-40344、CVE-2026-41145、CVE-2026-42600**（因为 SILO 保留了 `github.com/minio/minio` 模块路径，而上游通告使用开放版本区间）。这八项缺陷在此前版本中均已修复并通过回归测试，详见 [SFTP 公告](https://pkg.go.dev/vuln/GO-2025-3495)、[OIDC](/zh/blog/security/cve-2026-33322/)、[LDAP](/zh/blog/security/cve-2026-33419/)、[复制元数据](/zh/blog/security/cve-2026-34204/)、[CSV](/zh/blog/security/cve-2026-39414/)、[Snowball](/zh/blog/security/cve-2026-40344/)、[签名校验](/zh/blog/security/cve-2026-41145/) 与 [ReadMultiple](/zh/blog/security/cve-2026-42600/)。

## 兼容性与发布前验证 {#compatibility}

为避免已复现的终端表格输出变化、字符宽度计算差异及 NetBSD 交叉编译回归，本次固定保留 `tablewriter 0.0.5`、`go-humanize 1.0.1`、根模块 `go-runewidth 0.0.29` 及 `go-systemd/v22 22.6.0`（`xattr` 模块保留其既有宽度库组合）。此外：
- Kafka 通知目标在应用用户配置前显式保留协议版本默认值 `2.1`；
- DARE 加密继续使用 32 字节密钥与 v2 写入格式，并修复旧 v1 解封缓冲区处理；
- `pgzip` 保留对缺失校验尾部返回 `unexpected EOF` 的完整性检查。

10 月 22 日至 23 日的候选构建（与回退基线均基于 Go 1.27.3，持久化验收在单节点四盘 Linux arm64 环境执行）已完成以下验证：
- 全量编译、适用的 `-race` 与 lint 检查；
- 加密对象在新旧依赖栈之间的互读与回滚验证；
- 服务重启、缺失分片自愈恢复与 CLI 格式化输出校验；
- Console 真实对象上传下载、ZIP 归档预览、WebSocket 会话及监控指标图表验证。

10 月 24 日追加升级后的候选源码另行完成以下验证：

- silo-pkg、mcli、KES 的全量 race 测试，Console 的 API / pkg / cmd race 测试，以及 SILO 的全量测试和 SFTP、IAM、Parquet 专项 race 测试；五个项目的 lint、模块校验与依赖整洁性检查通过。
