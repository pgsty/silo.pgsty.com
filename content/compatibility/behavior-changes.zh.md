**标准 S3 应用通常无需修改代码即可从 MinIO 切换到 SILO，现代 `xl` / `xl-single` 数据卷也可原地挂载读取，无需重写对象。** 但从上游 MinIO 迁移到 SILO 属于**全集群协调停机切换**（不支持新旧节点混跑滚动升级），且安全加固与一致性修复对交付身份、IAM 策略求值、请求签名、Object Lock、多池写入及后台作业引入了明确的边界。

> [!IMPORTANT] 当前核查基线：SILO 20261112
> 本页完整覆盖从上游分叉基线 [`minio/minio@27742d469462`](https://github.com/minio/minio/commit/27742d469462e1561c776f88ca7a1f26816d69e2)（`2025-12-03`，位于上游最后发行版 `RELEASE.2025-10-15T17-29-55Z` 之后）至 **[SILO Server 20261112](/zh/blog/release/silo-20261112/)**（`RELEASE.2026-11-12T00-00-00Z`，源码 [`44e848fedf8c`](https://github.com/pgsty/silo/commit/44e848fedf8cec3d8c0da4b1aa8422390a2b7a8b)，内嵌 **[Console v2.7.2](/zh/blog/release/console-2.7.2/)** [`0e7953ff59c4`](https://github.com/pgsty/silo-console/commit/0e7953ff59c4a1eb77c7d203b265e6783ff18d01)、配套 **[mcli 20261112](/zh/blog/release/mcli-20261112/)** [`a37a9f054fba`](https://github.com/pgsty/mc/commit/a37a9f054fba828a0bbbceb4e9ff247ccf09c28d)、`silo-pkg v3.16.1`、Helm chart `7.0.5`、Go `1.27.4`）的全部用户可感知变化。高层分类见[三层兼容性总览](/zh/compatibility/)，操作步骤见[迁移指南](/zh/compatibility/migration/)。

## 现有 MinIO 集群能否直接在 SILO 上运行？ {#takeover}

评估存量集群能否直接接管时，需要把**磁盘格式能否直接读取**、**切换过程能否滚动混跑**、**切换后策略与后台任务是否按预期运行**三件事分开判断：

| 场景或边界                                                    | 判定结果                                          | SILO 20261112 实际行为                                                                                                                                    | 升级与运维要求                                                                                           |
| :------------------------------------------------------------ | :------------------------------------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------- |
| 现代单盘（`xl-single`）与分布式（`xl`）数据卷                 | {{< badge text="原地挂载" tone="success" >}}      | `.minio.sys/format.json` 与 XL 元数据头保持兼容；历史对象、多版本、分片上传、加密元数据与存量 IAM 记录可直接加载，无需逐对象导出重导                      | 切换前以只读方式确认 `.minio.sys/format.json` 为 `xl` 或 `xl-single`，并确认所有纠删集具备健康读仲裁     |
| 历史 `fs` 或 `gateway` 模式目录                               | {{< badge text="不支持直接挂载" tone="danger" >}} | 上游 MinIO 已于 `2022-10-29` 移除；SILO 启动时拒绝旧 `fs` 目录（注：现代单目录 `server /data` 实际使用 `xl-single`，可正常接管）                          | 按 [FS / Gateway 迁移流程](/zh/operations/deployments/baremetal-migrate-fs-gateway/)通过镜像同步导出迁移 |
| 跨产品逐节点混跑（MinIO 与 SILO 同时在线）                    | {{< badge text="禁止混跑" tone="danger" >}}       | 分布式启动会校验对端二进制校验和，内部 StorageREST 已移除私有 `/rmpl`（`ReadMultiple`），IAM 修订与复制对端协议也已演进                                   | 从上游 MinIO 切换到 SILO 必须按**全集群协调停机切换**执行，不要逐台滚动替换                              |
| 同池不同纠删集使用不同主机集合（自动布局通常 ≥ 18 台主机）    | {{< badge text="必须全停切换" tone="warning" >}}  | `20261109` 之前的进程将单池对象锁固定发往第 0 个纠删集，新进程发往对象所属纠删集；新旧混跑时锁域不一致，会失去互斥保护                                    | 升级到 `20261109` 及以上版本前，必须排空流量并停齐全部旧进程后再启动新进程                               |
| 多存储池集群在 SILO 版本间滚动升级                            | {{< badge text="排空并发写入" tone="warning" >}}  | 跨池条件写、锁顺序、批量删版本与暂停桶锁定的 `null` 版本保护需要全部节点升至 `20261112` 才能统一生效                                                      | 跨越混合版本窗口时排空或暂停并发 S3 写入                                                                 |
| 多站点复制与共享 IAM 切换                                     | {{< badge text="全站协同" tone="warning" >}}      | 持久 IAM 撤销墓碑（`20260916+`）与三态服务账号内联策略（`20261112`）若遇到未升级旧站点的账号编辑与回写，可能被旧语义覆盖                                  | 混合站点窗口期内禁止在旧站点编辑服务账号或策略；全站升齐后再核对有效策略                                 |
| 未完成的 Batch 后台作业（`expire`、`replicate`、`keyrotate`） | {{< badge text="升级前排空" tone="warning" >}}    | `20261109+` 使用绑定提交者的 `SILO-BATCH` v2 清单与报告；旧版运行中／排队／暂停作业不承诺跨版本续跑，且 `≤ 20261026` 拒绝读取 v2 记录                     | 升级前停止提交新作业，等待旧作业结束或主动取消；全部节点升齐后重新提交                                   |
| 原生 S3 归档恢复（`POST ?restore`）                           | {{< badge text="需全节点就绪" tone="warning" >}}  | `20261109+` 的两阶段无锁恢复要求集群内所有 peer 均支持新能力且网络可达，否则 `POST ?restore` 直接返回 `503`                                               | 全部节点升齐并确认对端连通后再执行归档恢复验收                                                           |
| 自定义 IAM 策略、OIDC/LDAP、TLS/KMS 与事件通知                | {{< badge text="按条件核查" tone="info" >}}       | 纯对象 ARN 不再授予 12 个桶级写动作、显式删版本要求 `s3:DeleteObjectVersion`、自助改密改为 `admin:ChangeMyPassword`、拒绝 HMAC OIDC、旧数据库通知需连接串 | 切换前核对代表性策略，并在真实网络环境中验证登录、KMS 解密、复制与通知投递                               |
| 切换后直接换回旧二进制回滚                                    | {{< badge text="需完整恢复点" tone="danger" >}}   | 能读对象不等于可安全降级：启动、扫描、IAM 变更、Batch v2 记录与桶墓碑会更新 `.minio.sys` 持久状态，旧二进制可能拒绝识别或破坏撤销历史                     | 切换前必须保留离线一致的 `.minio.sys`、IAM 导出与部署清单备份；回滚时须连同所有参与节点一起恢复          |

## 按起点版本速查升级重点 {#by-version}

选择你当前正在运行的版本，快速查看升级到 **SILO `20261112`** 时最关键的检查项；完整细节见下方 12 个领域对照表。

{{< tabs group="upgrade-origin" default="minio" label="选择当前运行版本" >}}
{{< tab label="从上游 MinIO（≤ 2025-10-15）迁移" value="minio" >}}

从上游 MinIO（例如最后正式版 `RELEASE.2025-10-15T17-29-55Z`）迁移到 `SILO 20261112` 时，会一次性跨越分叉以来的全部交付与安全边界：

- **切换方式与磁盘确认**：确认 `.minio.sys/format.json` 为 `xl` 或 `xl-single`，保留完整离线备份，并采用**全集群停机切换**（切勿 MinIO 与 SILO 混跑）。已有单节点原地迁移实录见[迁移案例](/zh/compatibility/migration/#single-node-case)。
- **部署与交付物身份（[第 1 节](#deployment)）**：镜像改为 `docker.io/pgsty/silo:RELEASE.2026-11-12T00-00-00Z`，二进制与 systemd 服务改为 `silo`，客户端包改为 `mcli`；容器内硬编码 `/usr/bin/minio` 需改为 `silo`；Helm 升级必须保留原有资源名称并显式固定 `image.tag`；自更新（`admin update` / `mcli update`）与 SUBNET 在线服务已停用。
- **IAM 策略与外部认证（[第 2 节](#iam)、[第 3 节](#object-authorization)）**：
  - 仅写 `arn:aws:s3:::bucket/*` 的策略不再自动获得 `PutBucketPolicy`、`PutBucketLifecycle`、`DeleteBucket` 等 12 个桶级写动作，需补齐裸桶 ARN `arn:aws:s3:::bucket`；
  - 带 `versionId` 的永久删除需要 `s3:DeleteObjectVersion`；仅写 `Deny s3:DeleteObject` 的防删策略需同步加上 `Deny s3:DeleteObjectVersion`；
  - 自助改密改看 `admin:ChangeMyPassword`（内置 `readonly` 默认不再允许自助改密）；新建或修改策略执行严格 JSON 校验并拒绝裸 ARN 前缀；
  - OIDC 拒绝 `client_secret` 对称 HMAC（`HS256/384/512`）与超过 4096 位的 RSA JWK；反向代理透传来源 IP 需配置 `MINIO_API_TRUSTED_PROXIES`。
- **外部依赖与后台任务（[第 8–10 节](#bucket-config)）**：PostgreSQL / MySQL 事件通知需改为 `connection_string` / `dsn_string`；桶级 CORS 配置开始真正生效；切换前排空未完成的 Batch 作业；切换后对每个节点执行真实签名 S3 读写与 Console 登录验证。

{{< /tab >}}
{{< tab label="从 SILO 20260804–20260903 升级" value="silo-202608-09" >}}

你已完成 `silo` / `mcli` 身份切换与首轮桶级 ARN、`DeleteObjectVersion`、OIDC HMAC 等分叉加固，升级到 `20261112` 重点核查 `20260916` 以来的变化：

- **权限与 IAM 协同（[第 2 节](#iam)）**：`20260916` 拆分 `admin:ChangeMyPassword` 并引入持久 IAM 撤销记录（需按 [IAM 升级指南](/zh/operations/replication/iam-upgrade/) 协同升级）；`20261018` 收紧委托管理凭据越权与根派生凭据保护；`20261112` 执行严格策略 JSON 解码，并将服务账号策略更新改为“省略保留、`{}` 清空回退继承”。
- **S3 标签与归档成员鉴权（[第 3 节](#object-authorization)）**：`GET`/`HEAD`（含双活代理、STS、预签名与匿名请求）仅在具备标签或锁读取权限时返回 `x-amz-tagging-count`、`X-Amz-Tagging` 与 `X-Amz-Object-Lock-*`；ZIP 压缩包内成员读取校验真实外层标签且不再隐式落盘索引。
- **拓扑停机与就绪门禁（[第 6–10 节](#replication)）**：≥ 18 台主机（或跨不同主机子集）的单池集群必须**全停切换**以对齐锁域；升级前排空或取消未完成的 Batch 作业（`SILO-BATCH` v2 清单不向后兼容）；混合版本期间 `POST ?restore` 返回 `503`；多池滚动窗口期内排空并发 S3 写入。
- **HTTP、TLS 与 Console（[第 11–12 节](#operations)）**：HTTP/1 请求头改用绝对读取截止时间；Go `1.27.4` 与 `-distroless` UBI 根证书收紧；内嵌 Console 升至 `v2.7.2`（游标分页、十语种 UI、文件夹用量扫描、内联策略三态编辑）。

{{< /tab >}}
{{< tab label="从 SILO 20260916–20261026 升级" value="silo-20260916-1026" >}}

从九月或十月版本升级到 `20261112` 时，重点处理以下升级门禁：

- **曾启用 `20260916` 可选 `strict` 分片列表模式的集群（[第 5 节](#multipart)）**：`20261018+` 已退役该实验开关（启动时忽略并打印告警），恢复缓存／精确键行为，不再提供持久分片枚举与严格取消。
- **单池锁域、Batch v2 与归档恢复门禁（`20261109` 引入）**：
  - 同池不同纠删集跨不同主机集合（自动布局通常 ≥ 18 台主机）时，必须排空并停齐旧进程后再启动 `20261112`；
  - 升级前排空或取消全部未完成 Batch 作业，升级后重新提交（`20261026` 拒绝读取 v2 清单）；
  - 全部节点升齐前，原生 `POST ?restore` 返回 `503`。
- **`20261112` 新增授权、锁与多池修复**：
  - 服务账号编辑默认保留现有内联策略，显式传入 `{}` 或关闭 **Restrict beyond user policy** 才恢复继承（混合站点窗口期内切勿在旧站点编辑服务账号）；
  - IAM、STS、桶策略、`mcli` 与 Console 全面启用严格策略 JSON 解码（拒绝未知字段与尾部多余内容）；
  - `DeleteObjects` 中所有显式携带 `VersionId` 的条目（无论桶是否开启 Object Lock）均改为顺序走单对象路径，大批量清版本耗时增加；
  - 版本暂停桶与前缀排除桶中已上锁的 `null` 版本受防覆盖、防遮蔽保护；修复压缩加密对象首帧内 `Range` 读取与跨池历史版本自复制。

{{< /tab >}}
{{< tab label="从 SILO 20261109 升级到 20261112" value="silo-20261109" >}}

`20261109` 已包含单池锁域对齐、`SILO-BATCH` v2 清单与两阶段归档恢复，升级到 `20261112` 主要关注以下增量变化（详见 [20261112 发行说明](/zh/blog/release/silo-20261112/#upgrade)）：

- **服务账号策略保留与重置（SN-2026-025）**：更新服务账号或访问密钥时，省略／`null` 策略会保留原有内联限制（含历史空内联拒绝策略），显式传 `{}` 或 `{"Statement":[]}` 才移除内联策略并恢复继承母账号。多站点升级期间避免在 `20261109` 站点编辑服务账号。
- **严格策略 JSON 与 SSE-KMS 上下文校验**：Server、Console `v2.7.2` 与 `mcli 20261112` 拒绝含未知字段、尾部垃圾内容或空 `Principal: {}` 的策略 JSON；`X-Amz-Server-Side-Encryption-Context` 非法输入统一返回 `400 InvalidArgument`（不再返回 `500`），且 `keyrotate` 持久保留 KMS 上下文并将旧 `XLV1` 流式重写为 `XLV2`。
- **S3 标签、ZIP 视图与签名边界（SN-2026-022 / -023 / -024）**：本地与双活代理 `GET`/`HEAD` 按权限过滤 `x-amz-tagging-count`、`X-Amz-Tagging` 与 `X-Amz-Object-Lock-*`；标签鉴权遇到读仲裁不足时保留 `5xx` 而非误判 `403`（`#294`）；ZIP 成员读取校验真实标签且不再隐式写回索引；认证的 `STREAMING-UNSIGNED-PAYLOAD-TRAILER` 强制 15 分钟时间窗，SigV4 拒绝范围日期不匹配与超 64 KiB 尾部头。
- **Object Lock、批量删版本与存储池**：暂停版本控制桶中已锁定的 `null` 版本拒绝普通覆盖与删除标记；`DeleteObjects` 中所有带显式 `VersionId` 的条目在全部桶中均按单对象顺序执行；多池滚动期间建议排空并发 S3 写入；修复压缩加密 `Range` 读取（`decryptSkip > 0`）、跨池历史版本自复制（`#343`）、`2024-04-28` 前旧 `xl.meta` 与 `UsesDataDir` 修订号分裂（`#332`、`#344`）以及池退役嵌套子键重扫与仲裁内离线盘判空（`#334`）。
- **Helm 升级**：使用 `helm upgrade --reuse-values` 升级到 chart `7.0.5` 时，显式传入 `--set image.tag=RELEASE.2026-11-12T00-00-00Z`。

## 1. 部署、交付物身份与外联边界 {#deployment}

| 场景                                    | 引入版本                  | 旧行为 → SILO 当前行为                                                                                                                                                          | 影响与处理建议                                                                                                                                                            |
| :-------------------------------------- | :------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 软件包、可执行文件与 systemd 服务       | `20260806+`               | `minio` / `minio.service` / `/usr/local/bin/minio` → 服务端包与二进制统一为 `silo`（`silo.service`），客户端包与二进制统一为 `mcli`；不安装 `/usr/bin/minio` 别名               | 更新启动脚本、监控探针与运维自动化；软件包迁移步骤见[原生软件包迁移](/zh/compatibility/binary/)                                                                           |

## 14. 切换前核查与回滚准备清单 {#upgrade}

准备将生产 MinIO 或早期 SILO 集群切换到 **SILO `20261112`** 时，按以下 5 步执行：

1. **确认磁盘格式、仲裁健康与拓扑切换方式**：以只读方式检查 `.minio.sys/format.json` 确认为 `xl` 或 `xl-single`，通过 `mcli admin info` 确认所有池与纠删集具备健康读仲裁。从上游 MinIO 迁移，或单池跨 ≥ 18 台主机（不同纠删集跨不同主机集合）从 `≤ 20261026` 升级时，规划**全集群停机切换窗口**；多池 SILO 滚动升级前排空并发 S3 写入。
2. **排空后台作业并留存离线一致恢复点**：停止提交新 Batch 作业，等待运行中／排队／暂停的 Batch 作业完成或主动取消；记录当前镜像 digest／二进制版本、systemd／Compose／Helm 渲染结果，导出 IAM 与桶元数据备份（`mcli admin cluster iam export`、`mcli admin cluster bucket export`），并在停机切流后保留 `.minio.sys` 与配置文件的一致恢复点。
3. **完成配置与策略预审**：将硬编码 `/usr/bin/minio` 改为 `silo`，Helm `--reuse-values` 显式附带 `--set image.tag=RELEASE.2026-11-12T00-00-00Z`；核查自定义策略中的 12 个桶级写动作（裸桶 ARN）、`s3:DeleteObjectVersion`、`admin:ChangeMyPassword`、严格 JSON 语法与服务账号内联策略；确认 OIDC 使用非对称 JWKS（RSA ≤ 4096 位）、PostgreSQL/MySQL 通知已改用连接串、`MINIO_API_TRUSTED_PROXIES` 与外部 TLS 根证书配置无误。
4. **原子切换并逐节点验证真实 S3 数据面**：启动新版本后，除确认 `silo healthcheck ready` 通过外，务必**直连每一个节点**执行一次有界签名 S3 写入、读取、条件请求与历史对象抽检（覆盖加密对象、分片对象、压缩对象 `Range` 读取），再验证 Console 登录、代表性子账号权限、复制队列与事件通知。
5. **在全站升齐后收尾后台任务与策略复核**：确认全部节点与复制对端站点均已稳定运行 `20261112` 后，再重新提交 Batch 作业、恢复归档 `POST ?restore` 请求，并复核多站点服务账号策略是否符合预期。
{.steps}

> [!CAUTION] 关于降级与回滚的硬边界
> **“新版本能直接挂载旧盘”不代表“上线运行一段时间后还能随时换回旧二进制”。** 进程启动、后台扫描、IAM 增删改（持久撤销墓碑与三态内联策略）、`SILO-BATCH` v2 清单写入以及桶配置墓碑都会更新 `.minio.sys` 持久元数据。一旦需要回退到旧版 MinIO 或早期 SILO，必须使用切换前留存的一致备份连同所有参与节点与复制对端同步恢复，切勿仅替换单台节点的容器镜像或二进制。
